# 阈值版本 3 下的 GPU 校准，2026-10-09

`m6-toploc-gpu-calibration` 的四个 GPU 格子（任务 8.1、8.2）：RTX 5090（种子 11）与 H800 PCIe（种子 12）在 `08ffbbf` 上各生成一个案例包（4,000 个诚实回答、每类作弊 150 个，prompt 按审计长度区间 150–300 个 token 补到目标长度），复核自己的与对方的。vLLM 0.30.0，PyTorch 2.13.0，驱动 580.105.08（RTX 5090）与 580.82.07（H800 PCIe）；指纹见 `summary.json`。

运行情况：两台机器上的 `ac-auditor` 都是手动重新编译的（`setup` 编译的二进制早于 `ac-auditor thresholds`；现在 `check`、`generate` 与 `recheck` 会重新编译它，校准脚本也会拒绝阈值与代码不一致的二进制）。H800 通过了 `check`。RTX 5090 的快速回归有一个诚实回答不通过（[gpu-check-v3-2026-10-09](../gpu-check-v3-2026-10-09/README.zh-CN.md)）；它的案例包照常生成（手动写入 `state/check.ok`），因为快速回归测的正是校准要决定的东西。

## 结果

诚实回答：不通过 / 无法判定（占样本数）；作弊：被放过（漏检）的个数。

| 格子（证明方 → 审计员） | 区间内：诚实 | int8 | 换模型、int4、篡改 prompt | 区间外：诚实 | int8 | 换模型、int4、篡改 prompt |
|---|---|---|---|---|---|---|
| RTX 5090 → RTX 5090 | 3,202 个中 9 / 20 | 119 个中 0 | 0 | 798 个中 0 / 6 | 31 个中 31 | 0 |
| RTX 5090 → H800 PCIe | 3,202 个中 9 / 20 | 119 个中 0 | 0 | 798 个中 0 / 6 | 31 个中 31 | 0 |
| H800 PCIe → RTX 5090 | 3,142 个中 13 / 24 | 117 个中 0 | 0 | 858 个中 1 / 8 | 32 个中 32 | 0 |
| H800 PCIe → H800 PCIe | 3,142 个中 8 / 24 | 117 个中 1 | 0 | 858 个中 1 / 8 | 32 个中 32 | 0 |

同一个案例包在两种 GPU 上复核，块指标不同（完全相同的不到 1%），但 99.7% 的案例判定结果相同：起决定作用的是证明方的 GPU，而不是审计员的。

换模型、int4 与篡改 prompt 在区间内外都离得很远（int4 的预填充均值最小为 8.31）。

- **区间内，诚实样本的尾部已与 int8 重叠。** 约 0.1% 的诚实回答预填充均值超过 0.97，最大 1.40（指数不一致最多 9 个），而 int8 的中位数是 1.24–1.31。没有任何一个上限能同时做到诚实 0 误判、int8 0 漏检。四个格子合计（区间内诚实 12,688 个，int8 474 个），预填充的其他上限取诚实最大值（指数不一致 9、中位数 1），解码上限取版本 3：

  | 区间内预填充均值上限 | 诚实误判 | int8 漏检 |
  |---|---|---|
  | 0.85（版本 3 暂定的均值；加上它的指数不一致上限 6 时为 39 个误判） | 38（0.30%） | 1 |
  | 1.00 | 27（0.21%） | 14 |
  | 1.10 | 20（0.16%） | 63 |
  | 1.20 | 15（0.12%） | 161 |
  | 1.41 | 2（0.02%，即下面的解码案例） | 382 |

  之前的长 prompt 实验（每格 100 个诚实回答）看到的诚实最大值是 0.72；每格 3,000 个时，尾部更长。
- **有两个诚实回答在两台审计机上都因解码块不通过**：种子 12 的 `honest-03727`（第 1 块：128 个指数中 83 个不同，均值 27.7）与 `honest-00036`（第 2 块：32 个不同，均值 4.6）。两种 GPU 上完全相同，说明问题出在 token 上，而不是数值计算上。最可能的原因是回答文本重新分词后 token 数相同但 ID 不同（生成日志中 H800 有 6 个、RTX 5090 有 4 个这样的回答），审计员于是按另一组 token 重算。去掉这两个后，诚实解码块不超过 (19, 7.96, 4)，在解码上限以内。
- **无法判定**：16,000 次诚实复核中 116 次（0.73%），全部是 `tokens cannot be re-created`（I-013）。

## 结论

`no thresholds`（规格 engineering/ci-quality-gates“GPU 跨硬件校准”）：在任何一格里，都不存在一组带区间的上限，能让区间内所有诚实回答通过、所有 int8 回答不通过。版本 3 未定稿，交用户决定（任务 9.1）。CPU 格子（任务 8.3、8.4）没有运行。

| D38 | 共识 | AC-BFT 终局性：按轮次进行两阶段投票（prepare、commit）并带锁定规则，阈值 `q = ⌊2W/3⌋ + 1`，轮次流水线化；超时从两个时隙开始、按 ×1.5 退避、上限 30 秒；根据权重超过 `W − q` 的成员已到达的轮次追赶。消息带版本号，绑定创世哈希与集合编号，用验证人的 ML-DSA-65 密钥签名（上下文 `agentcoin/bft-vote/v1`）；同一把密钥也用于出块封印（`agentcoin/aura-seal/v1`）和派生随机数秘密值。终局性证明是带版本号的 ≥ q 张 commit 票集合，只需创世哈希和集合即可验证；每个集合变更区块以及至少每 64 个区块保存一份。集合只在纪元边界变更。投票先持久化再发送 | M2 实现 |
| D39 | 违规 | PoA 阶段的违规处置：出块双签和 AC-BFT 投票双签通过无签名的授权交易上链举报，由 runtime 验证。同一授权节点集合内，每个违规者每类违规最多记录一条；违规者的第一条记录使其被移出下一纪元的集合（集合不会被移空），处罚只执行一次。罚没接口会得知已记录的违规类型；M3 起罚没按最重的一类计算，不累加。M2 不罚没（验证人没有质押，D9、D19） | M2 实现 |
| D40 | 排放 | 排放纪元长度 L 为创世参数（正式链 3,600 个区块），必须整除一个 4 年减半期的 126,230,400 个区块；计划量 `S(e) = (10,500,000 ATC >> n) × L / 126,230,400`（向下取整），其中 `n = e × L / 126,230,400`，在第 `(e + 1) × L + 1` 块结算。节点不信任 runtime、独立检查上限：只有结算区块能铸币，每次结算不超过 `2 × S`，累计铸币不超过累计计划量；所有销毁（手续费与小费的 80%、回收账户时的尘埃）都计入 `Emission::TotalBurned`。已发布的存储键 `Balances::TotalIssuance`、`Emission::TotalBurned`、`Emission::EpochLength` 永不更改 | M3 实现 |
| D41 | 治理 | PoA 阶段的管理权限是创世设定的 ML-DSA 多签（`pallet-collective` 实例 `PoaCouncil` 加 `pallet-poa-admin`）：决议达到门限 t（1 ≤ t ≤ 成员数，未投票视为反对）即作为 `AdminOrigin`，可以 Root 身份执行，覆盖 runtime 升级、国库支出和成员变更（成员与门限总是一起变更）。正式链必须在创世中给出成员。M8 移交链上治理 | M3 实现 |
| D42 | 国库 | 国库的比例份额按 40% 社区资助 : 60% 持币人国库拆分（创世参数 `community_share`，基点）；保底补足部分从其 30 天批次结束起在 2 年内线性解锁，只能用于审计或冷启动。持币人国库在 M8 持币人投票上线前锁定：没有任何模块调用能支出它，同一个调用过滤器（`HolderTreasuryLock`，同时用作 `BaseCallFilter` 和 `dispatch_as_root` 的过滤器）拒绝针对它的强制转账、强制改余额和直接写存储 | M3 实现 |
| D43 | 共识 | PoA→PoS 切换（修订 D19）：单向。每个验证人纪元边界做一次检查，全部有效质押（自质押加提名，不含解绑中）不低于**总发行量**的 10%、合格候选人（有效自质押 ≥ 发行量 0.1% 且未暂停参选）至少 21 个、区块高度不低于 63,115,200（2 年）时检查点达标；条件须在每个检查点连续成立 604,800 个区块（7 天），任一次不达标即重新计时。切换时选举产生的集合取代全部 PoA 授权节点；7 天内每个纪元公布预演选举。在此之前 PoA 多签可增删 PoA 授权节点（下一纪元边界生效，集合不可为空），切换后不再可以。节点从固定存储键独立复算每个检查点，拒绝提前、拖延或退回的切换；正式链必须使用这些取值（宪法第 1 层） | m3-pos |
| D44 | 共识 | 提名式 PoS：候选人自质押不低于发行量 0.1%，提名不低于 0.001%；每个提名人提名 1–16 个候选人；候选人最多 500 个、提名人最多 750 个（一个区块能算完的上限），名单满时挤出最小的一笔；每个验证人纪元运行带平衡的顺序 Phragmén；活跃集合规模 `K` 为参数（正式链 100，不小于切换所需候选人数、不超过纪元长度一半，存储上限 1,000，见 I-004）；AC-BFT 权重为 `max(1, 支撑额 / 10^12)` | m3-pos |
| D45 | 罚没 | 只罚验证人本人的自质押（锁定中和解绑中的都算）：投票双签 100%，出块双签 10%，同一集合按最重一类、不累加；罚没的 ATC 销毁并计入 `Emission::TotalBurned`；提名人永不被罚；掉线不罚本金。自质押解绑 28 天；提名通过全网队列解绑，2–28 天（参照 Polkadot RFC-0097）。PoA 阶段适用同一规则 | m3-pos |
| D46 | 奖励 | PoS 阶段安全预算在验证人之间按出块数分配，与质押多少无关（R1）；每份先付该验证人的佣金（5%–100%，调高 7 天后生效，调低下一纪元生效），其余按支撑额比例分配，自动发放；取整余数永不铸造。未揭示随机数的纪元不计工作分，连续 3 次则暂停参选；PoA 阶段只计数 | m3-pos |
| D47 | 许可证 | 按目录划分许可证（取代 D37）。GPL 区为 `node/`（含 `node/consensus/*`）、`services/`、`clients/wallet-cli/`、`tests/`、`scripts/`，采用 `GPL-3.0-or-later`，可以使用任何与 GPL 兼容的依赖。其余部分，包括 `crates/`、`pallets/`、`runtime/`、将来的 SDK 和绑定以及任何新目录，采用 `MIT OR Apache-2.0`，其依赖闭包（包括本仓库 GPL 区的 crate）中不得出现 GPL。每个 crate 都声明所在区的许可证，这两条规则由 CI 强制检查。贡献按所在目录的许可证授权（inbound = outbound，不设 CLA）；117712b 及之前的提交仍可按 MIT 使用 | relicense-layered |
| D48 | EVM | EVM 采用 `pallet-revive`，只运行 EVM 字节码（PolkaVM 合约、单独上传代码和按代码哈希实例化都被过滤）。合约交易就是一笔普通的 AgentCoin v5 交易，由 `PqAuthorize`（ML-DSA，`agentcoin/tx/v1`）授权，调用为 `Revive::call` 或 `Revive::instantiate_with_code`；所有以太坊签名入口（`eth_transact` 等，secp256k1 / EIP-155 / EIP-1559 交易）全部关闭。EVM 地址 = `keccak256(账户 ID)[12..]`（自动映射）；keccak 只用于 EVM 语义，不承担协议承诺。EVM 链 ID 4403（已核对 chainlist 未被占用），α 阶段 dev、local、测试网共用；`NativeToEthRatio` 为 1（ATC 与 wei 都是 18 位小数） | m4-evm |
| D49 | EVM | PQ 预编译地址固定、永不更改：`pq_verify` 0x0A01（按 AlgId 验证 ML-DSA，上下文 `agentcoin/evm-verify/v1`，任何失败都返回 `false`）、`blake3` 0x0A02、`poseidon2` 0x0A03、`stark_verify` 0x0A10 保留（调用一律回滚），按 revive 外部预编译布局排列（`0x…0a010000`）；都是纯函数，不创建合约账户，按基准权重计费。新增签名算法时只给 `pq_verify` 增加 AlgId 分支，地址与接口不变。revive 内置的以太坊预编译（`ecrecover`、bn128、KZG `point_eval`、`p256_verify`）只供应用使用，文档标注为非后量子，永不用于账户授权，协议也不依赖它们 | m4-evm |
| D50 | 发行 | 合约执行永不增发（D9）：每个新合约账户的存在性押金由交易签名者转入（`SetEvmPayer` 交易扩展 + `ReviveCurrency` 封装），没有付款人时铸币失败。合约销毁经 `OnBurn` 计入 `Emission::TotalBurned`；节点的发行量检查不变，照常 fail-closed。由此 revive 自带的基准（要铸币来准备账户）无法运行，runtime 使用 revive 的上游权重，并有测试断言最重的调用与部署放得进一笔普通交易 | m4-evm、license-internal-features |

| D52 | 密码学 | Poseidon2 = Plonky3 默认的 Goldilocks 宽 12 实例（`p3-goldilocks` 0.8：x^7，外部轮 8 + 内部轮 22），海绵速率 8、容量 4，输出 32 字节，字节编码单射（先写字节长度，再把输入加 `0x01` 与补零后按 7 字节小端组成元素）。调研门控没有找到实现 Poseidon2 作者参考实例、经过审阅的 no_std 库；用户接受 Plonky3 的实例，用 Plonky3 公布的置换向量代替作者向量核对（见 `ac-crypto` README） | m4-evm |
| D53 | 许可证 | 许可证边界（D47）约束的是会分发的构建。登记的内部开关（首批 `runtime-benchmarks`）可以引入登记的 GPL-only 依赖（首批 `pallet-revive-fixtures`，上游的基准合约）；打开内部开关构建的产物不得分发，谁分发谁按 GPL 分发。CI 检查两次闭包（去掉内部开关时不得有任何 GPL-only crate；打开全部 feature 时只允许登记的依赖），并检查正式 runtime 不含基准 API | license-internal-features |
| D54 | 市场 | 透明额度（D20 的 α 实现）采用按通道累计的凭证，而不是每个请求一张、带 nonce 的凭证。用户把 ATC 托管给网关，记入（用户, 网关）通道，并以 `agentcoin/voucher/v1` 用 ML-DSA 签署 `{创世哈希, 用户, 网关, 通道号, 累计美元额}`；链上每个通道只保存一个已兑付额计数，重放或较旧的凭证不付款，也没有不断增长的 nonce 集合。兑付时按参考汇率把增量向下取整换算，最多付出托管余额。取回托管和更换凭证密钥都在等待期（活链 1 天）后生效，期间此前的凭证仍可兑付；托管取空的通道重置（通道号 + 1），此前的凭证作废。只有结算调用 `Credit::redeem`，任何交易都调用不到 | m5-market-registry |
| D55 | 市场 | 市场质押以美元计，按参考汇率向上取整换算：T1 提供者 1,000 美元、T2 100 美元、网关 1,000 美元（网关费率上限 5%）。提供者处于活跃状态、质押不低于门槛、且两次心跳间隔不超过两个 600 块周期时为可服务；距上次心跳不少于半个周期的心跳免手续费。提供者与网关的质押解绑期为 7 天（604,800 块），长于结算挑战期。罚没与禁闭接口留给 M6 审计：任何交易都调用不到，PoA 管理多签也不能（D6），也没有 `force_*` 交易。提供者的加密公钥只接受 X-Wing；T0 与 TEE 证明在全量版之前一律拒绝 | m5-market-registry |
| D56 | 市场 | ATC/USD 参考汇率由 PoA 管理多签设置（MVP 不接预言机）：必须为正，相对上一个值最多变动 ±20%（含边界），距上次调整至少一天（86,400 块），每次调整都在链上可见。活链创世时不设汇率（设置之前没有提供者可服务）；开发预设初值为 1 ATC = 1 美元。M8 起改由代币治理加护栏设置 | m5-market-registry |

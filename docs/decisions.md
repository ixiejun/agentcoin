# AgentCoin Decision Log (D1–D52)

> This file consolidates the final conclusions of the requirements discussion. The discussion itself is in `docs/research/01–07`; the technical plans are in `docs/design/`.

| # | Area | Decision | Source |
|---|---|---|---|
| D1 | Vision | Build for the future: the protocol architecturally supports the full pipeline from pre-training to inference and keeps evolving | R2 |
| D2 | Incentives | Rewards attach only to work that the network actually used, that someone paid for, and that passed verification | R2 |
| D3 | Resources | Permissionless onboarding + tiers (T0 TEE / T1 data center / T2 consumer / T3 CPU / T4 storage) | R2 |
| D4 | Cryptography | Post-quantum from day one; the first implementation may be imperfect but must be pluggable and smoothly upgradable | R2 |
| D5 | Roadmap | Serve the best open-weight models first, then progressively train our own, aiming to match closed models | R2 |
| D6 | Neutrality | Protocol neutrality; content policy is decided by each service provider | R2 |
| D7 | Architecture | Own L1 built on the Polkadot SDK (Substrate); the AI work layer borrows JAM's refine/accumulate + ELVES pattern | R2/R3 |
| D8 | Use case | Year one: anyone calls top open-source model APIs anonymously from a wallet; on-chain-payable inference for agents | R2 |
| D9 | Token | No premine; Bitcoin-style fixed cap | R2 |
| D10 | Team | One person + AI | R2 |
| D11 | Emission | Hard cap + demand-driven emission + unemitted amounts roll over | R3 |
| D12 | Treasury | The DAO treasury is funded from emission | R3 |
| D13 | Signatures | 100% post-quantum signatures; give up the MetaMask / secp256k1 ecosystem | R3 |
| D14 | Token | Total supply 21,000,000 ATC, 18 decimals | R3 |
| D15 | Emission | Stepwise halving every 4 years (scheduled emission + rollover reserve; reserve drawdown capped at 1× the scheduled amount) | R4 |
| D16 | Allocation | Validators 10% (of the scheduled amount, unconditional) / market work 50% / public work 20% / treasury 20% | R4 |
| D17 | Brand | Project AgentCoin, token ATC | R4 |
| D18 | Treasury | Treasury = max(5% of scheduled amount as a floor, the 20% share proportional to actual work emission) (take the larger, do not add) (the floor vests linearly over 2 years and may only fund audits and cold start); two accounts: community grants + holder treasury | R5 |
| D19 | Genesis | PoA validators receive no security budget (it rolls over); switch to PoS automatically once stake ≥ 10% of circulating supply and validators ≥ N (switch conditions revised by D43) | R5 |
| D20 | MVP | Unified `Credit` interface; α ships non-ZK privacy measures; testnet uses only transparent credits; mainnet waits until anonymous vouchers pass an audit | R5 |
| D21 | Deliverables | Produce two technical plans: MVP and full version | R5 |
| D22 | Models | Community-model weights are fully open; about 5% of inference fees on this network go to training contributors | R6 |
| D23 | Pricing | Priced in USD, settled in ATC | R6 |
| D24 | Constitution | 21 million cap; no content censorship or geo-blocking at the protocol layer; no premine; PoA → PoS switch conditions | R6 |
| D25 | Governance | Bicameral: token house + contributor house (votes weighted by work score) | R6 |
| D26 | Storage | Dedicated storage layer (weights, checkpoints, datasets) | R6 |
| D27 | Privacy | MVP: L0 (private transfers, anonymous vouchers); full: L1 (private voting, sealed bids, private swaps); L2 interfaces reserved only; no L3 | R7 |
| D28 | Royalties | Incentives instead of enforcement (lineage declaration + routing priority) | R7 |
| D29 | Exchange rate | During the transition, governance sets a reference rate (with a cap on each adjustment) | R7 |
| D30 | Constitution | Three layers of protection: node-enforced invariants / constitution + guardrails / track-based day-to-day governance | R8 |
| D31 | Engineering | Primary development language is **Rust**; Python only for thin plugins inside inference/training engines (the engines are third-party) | R9 |
| D32 | Engineering | Spec-driven development (SDD) with OpenSpec (`openspec/`); specs first, then code | R10 |
| D33 | Documentation | Project docs are bilingual with English first (English at the canonical path, Chinese in `*.zh-CN.md`, linked at the top); OpenSpec artifacts are Chinese only; code comments and commit messages are English | R11 |
| D34 | Cryptography | AlgId is 1 byte per category and is also the SCALE enum index of the tagged types, so canonical encoding = on-chain SCALE encoding = what TypeInfo describes (one byte form, one numbering); `0x00` never allocated, `0xFF` reserved as extension marker | M0 apply |
| D35 | Cryptography | On-chain hashing is BLAKE3-256: block hashes, the extrinsics root and the state trie all use it (`Hashing = Blake3Hasher`). Documented exception: storage-key hashers of SDK pallets (`Blake2_128Concat` / `Twox64Concat` / `Twox128`) only spread keys and commit to nothing; AgentCoin's own pallets key by account ID with `Identity`. Fixed at genesis | M1 apply |
| D36 | Signatures | Transactions are v5 General transactions authorized by the `PqAuthorize` extension (first in the pipeline): ML-DSA over a BLAKE3 `derive_key` payload with context `agentcoin/tx/v1`; the first transaction registers the public key, later ones look it up; the legacy `Signed` form is closed (`NoClassicSignature`). Replaces "`AcMultiSignature` implements `Verify`" in the MVP plan §3.3 | M1 apply |
| D37 | Licensing | Source stays MIT. GPL-3.0 with Classpath exception is allowed only in the dependency closure of `node/` (and `tests/e2e`, which runs the node); `crates/`, `pallets/`, `runtime/` and `clients/` stay GPL-free, enforced in CI. `ac-node` binary releases ship a GPL source offer (superseded by D47) | M1 apply |
| D38 | Consensus | AC-BFT finality: two-phase voting (prepare, commit) in rounds with a locking rule, threshold `q = ⌊2W/3⌋ + 1`, pipelined rounds, timeouts from two slots backing off ×1.5 up to 30 s, and catch-up from the rounds that members worth more than `W − q` have reached. Messages are versioned, bound to the genesis hash and set id, and signed with the validator's ML-DSA-65 key (context `agentcoin/bft-vote/v1`); the same key seals blocks (`agentcoin/aura-seal/v1`) and derives randomness secrets. A finality proof is a versioned set of ≥ q commit votes, verifiable with only the genesis hash and the set; it is stored for every set-change block and at least every 64 blocks. Sets change only at epoch boundaries. Votes are persisted before they are sent | M2 apply |
| D39 | Offences | PoA offence handling: block-seal and AC-BFT vote double signing are reported on chain by unsigned, authorized extrinsics and verified by the runtime. Each offence kind is recorded at most once per offender and authority set; the offender's first record removes it from the next epoch's set (never emptying it) and punishment happens only once. The slash handler is told the kinds already recorded; from M3 slashing follows the most severe kind and never adds up. M2 slashes nothing (validators hold no stake, D9, D19) | M2 apply |
| D40 | Emission | The emission epoch length L is a genesis parameter (3,600 blocks on live chains) and must divide the 126,230,400 blocks of a 4-year halving period; the schedule is `S(e) = (10,500,000 ATC >> n) × L / 126,230,400` (rounded down) with `n = e × L / 126,230,400`, settled at block `(e + 1) × L + 1`. The node enforces the cap without trusting the runtime: minting happens only in settlement blocks, at most `2 × S` per settlement, and cumulative minting never exceeds the cumulative schedule; all burns (80% of fees and tips, reaped dust) are counted in `Emission::TotalBurned`. The published storage keys `Balances::TotalIssuance`, `Emission::TotalBurned`, `Emission::EpochLength` never change | M3 apply |
| D41 | Governance | In the PoA phase, administration is a genesis-configured ML-DSA multisig (`pallet-collective` instance `PoaCouncil` plus `pallet-poa-admin`): a motion reaching threshold t (1 ≤ t ≤ members, abstention counts as no) acts as `AdminOrigin` and can dispatch as Root, covering runtime upgrades, treasury spending and member changes (members and threshold always change together). Live chains must name the members at genesis. Handed over to on-chain governance in M8 | M3 apply |
| D42 | Treasury | The proportional treasury share is split 40% community grants : 60% holder treasury (genesis parameter `community_share`, basis points); the floor top-up vests linearly over 2 years from the end of its 30-day batch and may fund only audits or cold start. The holder treasury stays locked until holder voting ships in M8: no pallet call spends it, and one call filter (`HolderTreasuryLock`, applied both as `BaseCallFilter` and to `dispatch_as_root`) rejects forced transfers, forced balance changes and raw storage writes against it | M3 apply |
| D43 | Consensus | PoA → PoS switch (revises D19): one-way. At every validator-epoch boundary the checkpoint passes when all active stake (self-stake plus nominations, excluding unbonding) is at least 10% of the **total issuance**, at least 21 candidates are qualified (active self-stake ≥ 0.1% of the issuance, not paused) and the height is at least 63,115,200 (two years); the conditions must hold at every checkpoint for 604,800 blocks (seven days), any failure restarting the count. The switch replaces all PoA authorities with the elected set; during the seven days every epoch publishes a preview election. Until then the PoA multisig adds and removes PoA authorities (at the next boundary, never emptying the set); afterwards it cannot. The node recomputes every checkpoint from well-known keys and rejects early, delayed or reverted switches; live chains must use these values (constitution layer 1) | m3-pos |
| D44 | Consensus | Nominated PoS: candidates bond at least 0.1% and nominators at least 0.001% of the issuance; each nominator names 1–16 candidates; at most 500 candidates and 750 nominators (the most one block can elect), full lists evict their smallest entry; sequential Phragmén with balancing every validator epoch; the active-set size `K` is a parameter (100 on live chains, at least the switch's candidate count and at most half an epoch, storage bound 1,000, I-004); AC-BFT weight `max(1, backing / 10^12)` | m3-pos |
| D45 | Slashing | Only the validator's own self-stake is slashed, bonded and unbonding alike: vote double signing 100%, seal double signing 10%, the most severe kind per set without adding up; slashed ATC is burned and counted in `Emission::TotalBurned`; nominators are never slashed; going offline costs no principal. Self-stake unbonds in 28 days; nominations leave through a network-wide queue in 2–28 days (after Polkadot RFC-0097). The same rules apply in PoA | m3-pos |
| D46 | Rewards | In PoS the security budget is shared between validators by blocks authored, not by stake (R1); each share first pays the validator's commission (5%–100%, increases after 7 days, decreases at the next epoch), the rest goes pro rata to its backing, paid automatically; rounding remainders are never minted. An epoch with a missed randomness reveal earns no points, and three in a row pause the validator from elections; in PoA misses are only counted | m3-pos |
| D47 | Licensing | Licensing by directory (supersedes D37). The GPL zone — `node/` (including `node/consensus/*`), `services/`, `clients/wallet-cli/`, `tests/` and `scripts/` — is `GPL-3.0-or-later` and may use any GPL-compatible dependency. Everything else, including `crates/`, `pallets/`, `runtime/`, future SDKs and bindings and any new directory, is `MIT OR Apache-2.0`, and its dependency closure (including AgentCoin's own GPL-zone crates) must be GPL-free. Every crate declares its zone's licence, and CI enforces both rules. Contributions are licensed under their directory's licence (inbound = outbound, no CLA); commits up to 117712b remain available under MIT | relicense-layered |
| D48 | EVM | EVM via `pallet-revive` running EVM bytecode only (PolkaVM contracts, their upload and code-hash instantiation are filtered out). A contract transaction is an ordinary AgentCoin v5 transaction authorized by `PqAuthorize` (ML-DSA, `agentcoin/tx/v1`) whose call is `Revive::call` or `Revive::instantiate_with_code`; every Ethereum-signed entry (`eth_transact` and friends, secp256k1 / EIP-155 / EIP-1559 transactions) is closed. EVM address = `keccak256(AccountId)[12..]` (automatic mapping); keccak is used only for EVM semantics, never for protocol commitments. EVM chain ID 4403 (checked free in chainlist), shared by dev, local and testnet in α; `NativeToEthRatio` 1 (ATC and wei both have 18 decimals) | m4-evm |
| D49 | EVM | PQ precompiles at fixed addresses that never change: `pq_verify` 0x0A01 (ML-DSA by AlgId, context `agentcoin/evm-verify/v1`, any failure returns `false`), `blake3` 0x0A02, `poseidon2` 0x0A03, `stark_verify` 0x0A10 reserved (always reverts), laid out as revive external precompiles (`0x…0a010000`); pure, no contract account, charged benchmarked weights. New signature algorithms add AlgId branches to `pq_verify` without changing its address or interface. Revive's built-in Ethereum precompiles (`ecrecover`, bn128, KZG `point_eval`, `p256_verify`) stay available to applications only, are documented as not post-quantum and are never used for account authorization or by the protocol | m4-evm |
| D50 | Supply | Contract execution never mints (D9): the existential deposit of every new contract account is transferred from the transaction signer (`SetEvmPayer` extension + `ReviveCurrency` wrapper); with no payer, minting fails. Contract burns go through `OnBurn` and are counted in `Emission::TotalBurned`; the node's issuance check is unchanged and stays fail-closed. Consequence: revive's own benchmarks, which mint to set up accounts, cannot run, so the runtime uses revive's upstream weights, with a test that the heaviest call and deployment fit a normal extrinsic | m4-evm, license-internal-features |
| D51 | Tooling | Own eth-RPC adapter `ac-eth-rpc` (GPL zone, D47) in front of the node: Ethereum JSON-RPC reads (blocks by AC-BFT finality, balances, code, storage, calls, gas estimates, receipts, logs) from the node's RPC and runtime APIs, with an in-memory index; `eth_sendRawTransaction` accepts only PQ-signed native contract transactions. Foundry is used through the wallet as external signer (`ac-wallet evm deploy / send / broadcast`); the adapter never logs parameters or results | m4-evm |
| D52 | Cryptography | Poseidon2 = Plonky3's default Goldilocks width-12 instance (`p3-goldilocks` 0.8: x^7, 8 external + 22 internal rounds) in a sponge with rate 8 and capacity 4, 32-byte output, and an injective byte encoding (byte length first, then 7-byte little-endian elements with `0x01` and zero padding). The research gate found no reviewed no_std library for the Poseidon2 authors' reference instance; the user accepted Plonky3's instance, checked against Plonky3's published permutation vector instead of author vectors (documented in the `ac-crypto` README) | m4-evm |

# Test vector sources

All files in this directory are generated by `scripts/fetch-test-vectors.sh`, except the
repository-generated regression vectors listed at the end.
Do not edit the generated files by hand; re-run the script instead. Re-running it must
produce byte-identical output.

## Filtering rules

- **ML-DSA keyGen**: every parameter set (44 / 65 / 87), the first 10 test cases of each, fields `seed`, `pk`, `sk`.
- **ML-DSA sigGen**: groups with `deterministic = true`, `signatureInterface = external`, `preHash = pure`, `externalMu = false`; the first 10 cases per parameter set; fields `sk`, `message`, `context`, `signature`.
- **ML-DSA sigVer**: groups with `signatureInterface = external`, `preHash = pure`, `externalMu = false`; per parameter set every expected-pass case plus the first 7 expected-fail cases (so both outcomes are covered); fields `pk`, `message`, `context`, `signature`, `testPassed`, `reason`.
- **ML-KEM-768 keyGen**: parameter set ML-KEM-768, the first 10 cases; fields `d`, `z`, `ek`, `dk`.
- **ML-KEM-768 encapDecap**: encapsulation — the first 10 cases (`ek`, `m`, `c`, `k`); decapsulation — all cases (`dk`, `c`, `k`).
- **X-Wing**: all vectors of the specification repository. The specification text changed only editorially after draft-06 (ASN.1 module, wording); the vectors are identical to those shipped with the RustCrypto `x-wing` 0.1.0 crate, which implements draft-06. KEM AlgId `0x01` is bound to these semantics.
- **Argon2id**: the parameters, inputs (password, salt, secret, associated data) and the final tag of the reference KAT (Argon2id, version 19, m = 32 KiB, t = 3, p = 4). This is the test vector of RFC 9106 §5.3; the reference repository is used because it can be pinned by commit.
- **XChaCha20-Poly1305**: appendix A.3.1 of draft-irtf-cfrg-xchacha-03 (plaintext, AAD, key, 24-byte IV, ciphertext, tag), parsed from the draft text in the author's repository.
- **ChaCha20-Poly1305**: the AEAD test vector of RFC 8439 §2.8.2 (key, 12-byte nonce, AAD, plaintext, ciphertext, tag), taken from the `chacha20` test module of the RustCrypto crate's `tests/lib.rs`, which cites that section. The crate is pinned by the checksum crates.io and `Cargo.lock` record; rfc-editor.org is not reachable from CI.
- **BIP-39**: the English vectors whose entropy is 256 bits (24 words); fields `entropy` and `mnemonic` only. AgentCoin uses BIP-39 purely as an encoding of the 32-byte entropy, so the PBKDF2 seeds and xprv values are not used.

- **Poseidon2 (Goldilocks, width 12)**: the one known-answer vector Plonky3 publishes for its default width-12 instance, the input and expected output of `test_default_goldilocks_poseidon2_width_12`, as 16-digit hex field elements. It is Plonky3's own vector: the instance is not the Poseidon2 authors' reference instance, so no author vectors exist for it (user decision, m4-evm design D7).

Output is written with `jq -S` (sorted keys) so that re-running the script is byte-stable.

## Repository-generated vectors

- `account_id.json`: fixed ML-DSA-44 / ML-DSA-65 key seeds, the resulting public keys and the expected 32-byte account IDs (context `agentcoin 2026-09 account-id v1`, input `1-byte AlgId ‖ public key`). Regression only — once published these values must never change.
- `wallet_keys.json`: the all-zero-entropy BIP-39 test mnemonic and the account IDs of wallet keys derived from it (context `agentcoin 2026-09 wallet-key v1`, input `AlgId ‖ u32_le(index) ‖ entropy`), plus the development accounts `alice`, `bob`, `charlie`, `dave` (context `agentcoin 2026-09 dev-seed v1`) for ML-DSA-44 and ML-DSA-65. Produced by `examples/gen_wallet_key_vectors.rs`; regression only — never change these values. The mnemonic and development keys are public: never use them for real funds.
- `poseidon2_hash.json`: Poseidon2 hashes (`ac_crypto::poseidon2::hash`, encoding and sponge of m4-evm design D7) of the empty input, 31 bytes `00..1e`, 32 bytes `00..1f` and 1,000 bytes `i mod 251`. Regression only — once published these values must never change.
- `sealed_channel.json`: a sealed-channel session (`ac_crypto::sealed`, protocol version 1) from fixed inputs — X-Wing seed, 64 bytes of encapsulation randomness, an ML-DSA-44 signing seed signing deterministically, the handshake nonce and creation time — with the recipient digest, the encoded signed handshake, both derived keys and the wire form of two request chunks and one response chunk. Produced by `examples/gen_sealed_channel_vectors.rs`; regression only — never change these values (a new format needs a new protocol version and new contexts).

# market/auditor-agent Specification

## Purpose
规定审计员代理（MVP 方案 §5.5、§7 的 `ac-auditor`）的行为。审计员只复核自己以普通用户身份发起的推理，用声明的模型在本地复算激活值，与提供者交来的 TOPLOC 证明比对并给出判定，使换模型、降精度或篡改 prompt 的提供者能被发现，而用户内容从不进入审计流程。本阶段覆盖“复核一次推理”；神秘顾客的发起、抽样与判定上链由后续变更加入。

## Requirements

### Requirement: 复核一次推理
审计员代理 SHALL 能复核一次已完成的推理。输入为：链上模型 ID 及其登记信息、请求的消息列表、提供者返回的输出文本与结束原因、返回的用量（输入与输出 token 数）、双签收据，以及随收据交回的 TOPLOC 证明（可以没有）。复核结果 SHALL 是以下三者之一：
- **通过**；
- **不通过**，原因为：没有证明、证明与收据承诺不符、证明参数或块数不符、或某块超出阈值（指明块序号与指标）；
- **无法判定**，原因为：模型登记的精度不受支持、无法重现 token、复核引擎出错或不可用。

复核前审计员代理 SHALL 检查收据中的模型、输入与输出 token 数与输入一致，不一致时结果为无法判定。

#### Scenario: 诚实提供者
- **WHEN** 提供者用登记的模型与 bfloat16 精度完成推理并交出证明，审计员复核
- **THEN** 结果为通过

#### Scenario: 换了模型
- **WHEN** 提供者用同架构的另一个模型完成推理并按其激活值交出证明，审计员按登记的模型复核
- **THEN** 结果为不通过，原因指明超出阈值的块

#### Scenario: 证明与承诺不符
- **WHEN** 交回的证明复算出的承诺与收据中的承诺不同
- **THEN** 结果为不通过，原因为证明与承诺不符

### Requirement: 缺少证明即不通过
审计员复核的收据若 TOPLOC 承诺为全零（没有证明），结果 SHALL 为“不通过（没有证明）”，无论原因是提供者未运行插件、插件未能交出完整候选还是其他情况。该规则只适用于审计员的复核；普通用户收据的有效性、付费与结算规则不因此改变。

#### Scenario: 全零承诺
- **WHEN** 审计员复核一张 TOPLOC 承诺为全零、没有证明的收据，且模型登记为 bfloat16
- **THEN** 结果为不通过，原因为没有证明

### Requirement: 只复核 bfloat16 模型
本阶段只有登记精度为 bfloat16 的模型接受 TOPLOC 复核。登记为其他精度的模型，复核结果 SHALL 为“无法判定（精度不支持）”，且 MUST NOT 被判为不通过（包括没有证明的情况）。

#### Scenario: int4 模型
- **WHEN** 审计员复核一次登记精度为 int4 的模型的推理
- **THEN** 结果为无法判定，原因为精度不支持

### Requirement: 重现 token
审计员代理 SHALL 用复核引擎、按登记模型的分词器与对话模板重现 token：prompt 的 token 由消息列表经对话模板得到；输出的 token 由输出文本分词得到。只有同时满足以下条件时才继续复算，否则结果 SHALL 为“无法判定（无法重现 token）”：
- prompt 的 token 数等于返回的输入 token 数；
- 输出的 token 解码后与输出文本完全相同；
- 结束原因为生成结束符时，输出文本的 token 数等于输出 token 数减 1；结束原因为达到长度上限时，等于输出 token 数；其他结束原因一律无法判定。

复算所用的序列 SHALL 为 prompt 的 token 后接输出的前“输出 token 数 − 1”个 token（最后一个生成的 token 不经过前向计算），复算结果按原推理的分块（prompt 为预填充，其后每个 token 为一个解码步骤）重组后与证明比对。

#### Scenario: token 数不符
- **WHEN** 输出文本重新分词后比收据的输出 token 数少 2 个
- **THEN** 结果为无法判定，原因为无法重现 token

#### Scenario: 因长度上限结束
- **WHEN** 一次推理因达到长度上限而结束，输出 40 个 token
- **THEN** 复算序列为 prompt 的 token 加输出的前 39 个 token，证明按 1 + ⌈39 / 32⌉ = 3 块比对

### Requirement: 复核不记录内容
审计员代理 MUST NOT 把复核所用的消息、输出文本、token 或激活值候选写入日志；日志只允许包含请求 ID、模型 ID、计数、各块指标与判定结果。

#### Scenario: 日志中没有内容
- **WHEN** 用含唯一标记字符串的消息完成一次复核，并在调试日志级别下运行
- **THEN** 审计员代理与复核引擎的日志中找不到该标记字符串

### Requirement: 审计证据
审计员代理 SHALL 能把一次复核的输入（请求的 messages、回答文本、结束原因、用量、双签收据与 TOPLOC 证明）导出为 `market/audit`“审计证据与承诺”规定的证据编码，并给出其承诺，供提交“不通过”裁决。审计员代理 SHALL 能从一份证据与链上记录的承诺复核：先检查证据的承诺等于给定承诺，不相等时结果为“证据与承诺不符”，不进行复核；相等时按“复核一次推理”复核，结果与从原案例复核相同。导出与复核都 MUST NOT 把证据内容写入日志。

#### Scenario: 导出再复核
- **WHEN** 把一次判为“不通过”的复核案例导出为证据，再以导出的承诺从证据复核
- **THEN** 结果仍为“不通过”，原因与原复核相同

#### Scenario: 承诺不符
- **WHEN** 以一个与证据不符的承诺从证据复核
- **THEN** 结果为“证据与承诺不符”，不调用复核引擎

### Requirement: 审计员代理服务
审计员代理 SHALL 提供长期运行的服务模式，以一个已登记的审计员账户运行，配置包括：审计员钱包、一个或多个付款账户钱包、可复核的模型及其复核引擎、证据服务的监听地址与对外地址、数据目录。启动时代理 SHALL 检查：审计员账户已登记且未在退出中；每个付款账户都不是审计员账户本身；每个可复核模型都在链上登记。任一检查失败时代理 MUST 拒绝启动并说明原因。链上登记的证据地址或加密公钥与配置不同时，代理 SHALL 提交交易更新为配置的值。

#### Scenario: 未登记的审计员
- **WHEN** 以一个未登记为审计员的账户启动代理
- **THEN** 代理拒绝启动并说明账户未登记

#### Scenario: 付款账户与审计员账户相同
- **WHEN** 配置的付款账户之一就是审计员账户
- **THEN** 代理拒绝启动

#### Scenario: 自动登记证据地址
- **WHEN** 代理启动时链上没有该审计员的证据地址
- **THEN** 代理提交交易，此后查询该审计员的证据地址返回配置的地址与代理的加密公钥

### Requirement: 神秘顾客请求
在每个有种子的审计轮次，代理 SHALL 查询本审计员被分配的提供者，并对每个被分配的提供者发起一次审计请求：
- 发起时刻在本轮内均匀随机，且留出足够在本轮结束前完成复核与提交的余量；
- 模型从该提供者登记、且本代理配置了复核引擎的模型中随机选择；没有这样的模型时代理 SHALL 跳过该提供者并记录计数，不提交裁决；
- 网关从活跃且付款账户在其处有透明额度通道的网关中随机选择，付款账户从配置的付款账户中随机选择；
- 请求为指定该提供者的请求（`market/gateway-service`“指定提供者的请求”），对用户可见的形式与普通用户请求相同，内容为一条审计 prompt。

请求失败（没有可服务的提供者、网关错误、提供者失败）时代理 SHALL 在本轮余量内换一个网关或付款账户重试，仍失败则不提交裁决并记录原因。审计员代理 MUST NOT 审计自己作为提供者或网关的账户。

#### Scenario: 每个被分配的提供者一次请求
- **WHEN** 某轮本审计员被分配给提供者 P 与 Q
- **THEN** 本轮内代理分别对 P 与 Q 各发起一次指定提供者的请求，收据中的提供者分别为 P 与 Q

#### Scenario: 没有可复核的模型
- **WHEN** 被分配的提供者只登记了代理没有配置复核引擎的模型
- **THEN** 代理不向它发请求、不提交裁决，跳过计数加 1

#### Scenario: 发起时刻随机
- **WHEN** 统计代理在多轮中对同一提供者的发起时刻相对轮次起点的偏移
- **THEN** 偏移分布在整个可用区间内，不集中在固定时刻

### Requirement: 审计 prompt
审计 prompt SHALL 来自内置生成器，或来自运营者给出的题库文件（每项为一组 Chat Completions 消息）；配置题库时代理 SHALL 按配置的比例混合两者。内置生成器 SHALL 以密码学安全的随机数在多种任务类型、主题与措辞之间组合，生成长度不一的单轮或多轮对话，并在配置范围内随机选择输出 token 上限；任意两次生成的 prompt MUST NOT 含有可用于识别审计的固定标记。题库文件无法解析时代理 MUST 拒绝启动。

#### Scenario: prompt 多样
- **WHEN** 内置生成器连续生成 1,000 个 prompt
- **THEN** 其中互不相同的 prompt 至少 990 个，且没有任何长度不小于 16 个字符的子串出现在全部 prompt 中

#### Scenario: 题库无效
- **WHEN** 配置的题库文件不是有效的消息列表
- **THEN** 代理拒绝启动

### Requirement: 自动复核与提交裁决
审计请求完成后，代理 SHALL 按“复核一次推理”立即复核，并在本轮结束前提交裁决：通过与无法判定直接提交；不通过时 SHALL 先把证据（`market/audit`“审计证据与承诺”）保存到数据目录，再提交带该证据承诺的裁决。裁决的阈值版本 SHALL 等于链上当前接受的版本；代理所知的阈值版本与链上不同时，代理 MUST NOT 提交裁决，并报告版本不符。提交失败时代理 SHALL 记录链返回的原因，本轮结束后不再重试。

#### Scenario: 作弊的提供者
- **WHEN** 被分配的提供者以另一模型的激活值交出证明
- **THEN** 代理在本轮内提交“不通过”裁决，链上记录的证据承诺等于数据目录中所存证据的承诺

#### Scenario: 诚实的提供者
- **WHEN** 被分配的提供者诚实服务
- **THEN** 代理在本轮内提交“通过”裁决，数据目录中不保存证据

#### Scenario: 阈值版本不符
- **WHEN** 链上接受的阈值版本高于代理内置的版本
- **THEN** 代理不提交裁决并报告阈值版本不符

### Requirement: 证据保存与交付
代理 SHALL 保存自己提交的每条“不通过”裁决的证据，直到该裁决不可能再被用于开启争议、且引用它的争议都已关闭，之后删除。代理 SHALL 在登记的证据地址上经密封通道（`crypto/sealed-channel`）应答证据请求：请求给出争议编号与证据承诺；代理 SHALL 按链上记录核对——请求方是该争议的复核人、该争议未关闭、本审计员是该争议的提出者、且所请求的承诺是本审计员在该争议中裁决所带的承诺——全部满足才交付证据字节，否则 SHALL 拒绝且不透露证据是否存在。代理日志中关于证据交付的记录 MUST 只包含争议编号、请求方账户与结果。

#### Scenario: 复核人取得证据
- **WHEN** 争议的复核人向提出者的证据地址索取该争议中的证据
- **THEN** 复核人收到证据，其承诺等于链上该裁决的证据承诺

#### Scenario: 非复核人被拒绝
- **WHEN** 一个不是该争议复核人的账户索取证据
- **THEN** 代理拒绝，不返回任何证据内容

#### Scenario: 争议关闭后删除
- **WHEN** 引用某证据的争议已关闭，且该裁决已不可能再开启争议
- **THEN** 代理的数据目录中不再有该证据

### Requirement: 升级复核与投票
代理 SHALL 周期性地查询未关闭的争议，对本审计员被抽为复核人、尚未投票的每个争议：向每名提出者的证据地址索取其裁决的证据，检查证据的承诺等于链上裁决的承诺、证据中的收据与链上裁决的收据一致，然后按裁决的阈值版本复核。至少两名不同提出者的证据复核结果为“不通过”时，代理 SHALL 投“确认”；否则（包括拿不到证据、承诺不符、收据不符、复核结果为通过或因证据本身无法判定）SHALL 投“驳回”。本机复核引擎出错或不可用时，代理 SHALL 重试，到投票期限前仍不可用则 MUST NOT 投票并报告；代理不认识裁决的阈值版本时同样 MUST NOT 投票。

#### Scenario: 确认作弊
- **WHEN** 两名提出者对同一提供者的不通过裁决都基于真实的作弊证据，代理是该争议的复核人
- **THEN** 代理取得两份证据，复核都为不通过，投“确认”

#### Scenario: 驳回伪造的不通过
- **WHEN** 提出者的证据复核结果为通过
- **THEN** 代理投“驳回”

#### Scenario: 拿不到证据
- **WHEN** 提出者的证据地址在投票期限内一直无法连接
- **THEN** 代理投“驳回”

#### Scenario: 本机引擎不可用
- **WHEN** 代理是复核人，但其复核引擎在整个投票期限内都不可用
- **THEN** 代理不投票，并报告引擎不可用

### Requirement: 审计付款账户
代理 SHALL 用配置的付款账户经透明额度通道为审计请求付费，规则与本地推理代理相同（逐请求校验收据与证明后签发累计凭证、已付总额持久化、重启后不重复付费、可选的花费上限）。代理 SHALL 在每个付款账户的通道余额不足或达到花费上限时停止使用该账户并报告；全部付款账户都不可用时，代理 SHALL 继续履行证据交付与投票，并报告无法发起审计请求。付款账户 MUST NOT 出现在任何裁决、投票或证据地址交易中。

#### Scenario: 付款账户耗尽
- **WHEN** 唯一的付款账户达到花费上限
- **THEN** 代理不再发起审计请求并报告，仍然应答证据请求并对争议投票

#### Scenario: 重启后不重复付费
- **WHEN** 代理用某付款账户完成若干审计请求后重启，再发起一个请求
- **THEN** 新凭证的累计金额等于重启前已付总额加上新请求的费用

### Requirement: 代理不记录内容
服务模式下，代理 MUST NOT 把审计 prompt、回答、证据内容或 token 写入日志；日志只允许包含轮次、提供者、网关、模型 ID、请求 ID、结果与原因、各块指标、交易哈希与计数。

#### Scenario: 日志中没有审计 prompt
- **WHEN** 用含唯一标记字符串的题库运行代理若干轮，并在调试日志级别下运行
- **THEN** 代理的日志中找不到该标记字符串，数据目录中只有“不通过”裁决的证据文件含有它

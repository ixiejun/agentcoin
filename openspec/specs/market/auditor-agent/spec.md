# market/auditor-agent Specification

## Purpose
规定审计员代理（MVP 方案 §5.5、§7 的 `ac-auditor`）的行为。审计员只复核自己以普通用户身份发起的推理，用声明的模型在本地复算激活值，与提供者交来的 TOPLOC 证明比对并给出判定，使换模型、降精度或篡改 prompt 的提供者能被发现，而用户内容从不进入审计流程。本阶段覆盖“复核一次推理”；神秘顾客的发起、抽样与判定上链由后续变更加入。

## Requirements

### Requirement: 复核一次推理
审计员代理 SHALL 能复核一次已完成的推理。输入为：链上模型 ID 及其登记信息、请求的消息列表、提供者返回的输出文本与结束原因、返回的用量（输入与输出 token 数）、双签收据，以及随收据交回的 TOPLOC 证明、盐与两组 token ID（可以没有）。复核结果 SHALL 是以下三者之一：
- **通过**；
- **不通过**，原因为：没有证明、证明与收据承诺不符、证明参数或块数不符、prompt 与请求不符，或某块超出阈值（指明块序号与指标）；
- **无法判定**，原因为：模型登记的精度不受支持、回答与 token 不符、复核引擎出错或不可用。

复核前审计员代理 SHALL 检查收据中的模型、输入与输出 token 数与输入一致，不一致时结果为无法判定。案例的消息列表、盐与 token ID 打不开收据中的内容承诺（包括 TOPLOC 承诺非零而案例没有 token ID）时，结果 SHALL 为“内容与收据不符”：这不是对提供者的结论，代理 MUST NOT 据此提交裁决。

#### Scenario: 诚实提供者
- **WHEN** 提供者用登记的模型与 bfloat16 精度完成推理并交出证明，审计员复核
- **THEN** 结果为通过

#### Scenario: 换了模型
- **WHEN** 提供者用同架构的另一个模型完成推理并按其激活值交出证明，审计员按登记的模型复核
- **THEN** 结果为不通过，原因指明超出阈值的块

#### Scenario: 证明与承诺不符
- **WHEN** 交回的证明复算出的承诺与收据中的承诺不同
- **THEN** 结果为不通过，原因为证明与承诺不符

#### Scenario: 内容与收据不符
- **WHEN** 案例中的一条消息被改动后再复核
- **THEN** 结果为“内容与收据不符”，不调用复核引擎，也不产生裁决

### Requirement: 缺少证明即不通过
审计员复核的收据若 TOPLOC 承诺为全零（没有证明），结果 SHALL 为“不通过（没有证明）”，无论原因是提供者未运行插件、插件未能交出完整候选还是其他情况。该规则只适用于审计员的复核；普通用户收据的有效性、付费与结算规则不因此改变。

#### Scenario: 全零承诺
- **WHEN** 审计员复核一张 TOPLOC 承诺为全零、没有证明的收据，且模型登记为 bfloat16
- **THEN** 结果为不通过，原因为没有证明

### Requirement: 只复核 bfloat16 模型
本阶段只有登记精度为 bfloat16 的模型接受 TOPLOC 复核。登记为其他精度的模型，复核结果 SHALL 为“无法判定（精度不支持）”，且 MUST NOT 被判为不通过（包括没有证明的情况）。

#### Scenario: int4 模型
- **WHEN** 审计员复核一次登记精度为 int4 的模型的推理
- **THEN** 结果为无法判定，原因为精度不支持

### Requirement: 按承诺的 token 复算
审计员代理 SHALL 按收据内容承诺所绑定的 token 复算，不再由文本重新分词：
- prompt：按登记模型的分词器与对话模板由消息列表得到 token，它 MUST 与承诺的 prompt token ID 完全相同，否则结果 SHALL 为“不通过（prompt 与请求不符）”；
- 复算序列 SHALL 为承诺的 prompt token 后接承诺的输出 token 的前“输出 token 数 − 1”个（最后一个生成的 token 不经过前向计算），无论结束原因为何；复算结果按原推理的分块（prompt 为预填充，其后每个 token 为一个解码步骤）重组后与证明比对；
- 回答：承诺的输出 token 解码后（不显示特殊 token）MUST 与回答文本相同。不同时复算照常进行：按阈值判为不通过时结果为不通过；否则结果 SHALL 为“无法判定（回答与 token 不符）”。

#### Scenario: 非标准切分的诚实回答
- **WHEN** 诚实提供者的回答文本重新分词会得到与生成时不同的 token ID，内容承诺绑定的是生成时的 token
- **THEN** 复算使用承诺的 token，结果为通过

#### Scenario: 隐藏的系统提示词
- **WHEN** 提供者在请求前加入了用户没有发送的系统提示词，并如实承诺了它实际使用的 prompt token
- **THEN** 结果为不通过，原因为 prompt 与请求不符

#### Scenario: 回答与 token 不符
- **WHEN** 提供者如实计算并承诺了 token，但交给用户的回答文本与这些 token 解码的文本不同
- **THEN** 复算按承诺的 token 进行；按阈值通过时结果为无法判定，原因为回答与 token 不符

#### Scenario: token 数不符
- **WHEN** 案例中承诺的输出 token 比收据的输出 token 数少 2 个
- **THEN** 结果为“内容与收据不符”（这样的收据不会被网关联署，也不会被代理付费），不产生裁决

#### Scenario: 因长度上限结束
- **WHEN** 一次推理因达到长度上限而结束，输出 40 个 token
- **THEN** 复算序列为承诺的 prompt token 加承诺的输出 token 的前 39 个，证明按 1 + ⌈39 / 32⌉ = 3 块比对

### Requirement: 复核不记录内容
审计员代理 MUST NOT 把复核所用的消息、输出文本、token 或激活值候选写入日志；日志只允许包含请求 ID、模型 ID、计数、各块指标与判定结果。

#### Scenario: 日志中没有内容
- **WHEN** 用含唯一标记字符串的消息完成一次复核，并在调试日志级别下运行
- **THEN** 审计员代理与复核引擎的日志中找不到该标记字符串

### Requirement: 审计证据
审计员代理 SHALL 能把一次复核的输入（请求的 messages、回答文本、结束原因、用量、双签收据、TOPLOC 证明以及盐与两组 token ID）导出为 `market/audit`“审计证据与承诺”规定的证据编码，并给出其承诺，供提交“不通过”裁决与带统计量的裁决。审计员代理 SHALL 能从一份证据与链上记录的承诺复核：先检查证据的承诺等于给定承诺，再检查证据的内容能打开其中收据的内容承诺，任一不成立时结果为“证据与承诺不符”，不进行复核；相等时按“复核一次推理”复核，结果与从原案例复核相同，并给出该次复核的统计量（prompt token 数、预填充块尾数误差均值、各解码块尾数误差均值的平均值与解码块数）。导出与复核都 MUST NOT 把证据内容写入日志。

#### Scenario: 导出再复核
- **WHEN** 把一次判为“不通过”的复核案例导出为证据，再以导出的承诺从证据复核
- **THEN** 结果仍为“不通过”，原因与原复核相同

#### Scenario: 承诺不符
- **WHEN** 以一个与证据不符的承诺从证据复核
- **THEN** 结果为“证据与承诺不符”，不调用复核引擎

#### Scenario: 从证据得到统计量
- **WHEN** 把一次判为“通过”的复核案例导出为证据，再从证据复核
- **THEN** 结果为通过，并给出统计量；同一台机器上两次得到的统计量相同

#### Scenario: 证据中的内容被改动
- **WHEN** 提出者改动证据中的一条消息或一个 token ID，并以改动后证据的承诺提交“不通过”
- **THEN** 从该证据复核的结果为“证据与承诺不符”，而不是不通过

### Requirement: 审计员代理服务
审计员代理 SHALL 提供长期运行的服务模式，以一个已登记的审计员账户运行，配置包括：审计员钱包、一个或多个付款账户钱包、可复核的模型及其复核引擎、证据服务的监听地址与对外地址、数据目录。启动时代理 SHALL 检查：审计员账户已登记且未在退出中；每个付款账户都不是审计员账户本身；每个可复核模型都在链上登记。任一检查失败时代理 MUST 拒绝启动并说明原因。链上登记的证据地址或加密公钥与配置不同时，代理 SHALL 提交交易更新为配置的值。

#### Scenario: 未登记的审计员
- **WHEN** 以一个未登记为审计员的账户启动代理
- **THEN** 代理拒绝启动并说明账户未登记

#### Scenario: 付款账户与审计员账户相同
- **WHEN** 配置的付款账户之一就是审计员账户
- **THEN** 代理拒绝启动

#### Scenario: 自动登记证据地址
- **WHEN** 代理启动时链上没有该审计员的证据地址
- **THEN** 代理提交交易，此后查询该审计员的证据地址返回配置的地址与代理的加密公钥

### Requirement: 神秘顾客请求
在每个有种子的审计轮次，代理 SHALL 查询本审计员被分配的提供者，并对每个被分配的提供者发起一次审计请求：
- 发起时刻在本轮内均匀随机，且留出足够在本轮结束前完成复核与提交的余量；
- 模型从该提供者登记、在链上有审计档案（`market/audit`“按模型的审计档案”）、且本代理配置了复核引擎的模型中随机选择；没有这样的模型时代理 SHALL 跳过该提供者并记录计数，不提交裁决；
- 网关从活跃且付款账户在其处有透明额度通道的网关中随机选择，付款账户从配置的付款账户中随机选择；
- 请求为指定该提供者的请求（`market/gateway-service`“指定提供者的请求”），对用户可见的形式与普通用户请求相同，内容为一条审计 prompt，不带停止字符串，只要一个回答。

代理 SHALL 按本地推理代理的规则（`clients/wallet-cli`“本地推理代理”）校验交回的收据、证明与内容承诺后才付费；校验失败时不付费、不提交裁决，记录原因并在本轮余量内换一个网关重试。请求失败（没有可服务的提供者、网关错误、提供者失败）时代理 SHALL 在本轮余量内换一个网关或付款账户重试，仍失败则不提交裁决并记录原因。审计员代理 MUST NOT 审计自己作为提供者或网关的账户。

#### Scenario: 每个被分配的提供者一次请求
- **WHEN** 某轮本审计员被分配给提供者 P 与 Q
- **THEN** 本轮内代理分别对 P 与 Q 各发起一次指定提供者的请求，收据中的提供者分别为 P 与 Q

#### Scenario: 没有可复核的模型
- **WHEN** 被分配的提供者只登记了代理没有配置复核引擎的模型
- **THEN** 代理不向它发请求、不提交裁决，跳过计数加 1

#### Scenario: 只审计已校准的模型
- **WHEN** 被分配的提供者登记了模型 M1（有审计档案）与 M2（未校准），代理两者都配置了复核引擎
- **THEN** 代理的审计请求只使用 M1

#### Scenario: 发起时刻随机
- **WHEN** 统计代理在多轮中对同一提供者的发起时刻相对轮次起点的偏移
- **THEN** 偏移分布在整个可用区间内，不集中在固定时刻

#### Scenario: 内容承诺不符的收据
- **WHEN** 网关交回的 token ID 打不开收据中的内容承诺
- **THEN** 代理不为该请求付费、不提交裁决，并记录原因

### Requirement: 审计 prompt
审计 prompt SHALL 来自内置生成器，或来自运营者给出的题库文件（每项为一组 Chat Completions 消息）；配置题库时代理 SHALL 按配置的比例混合两者。内置生成器 SHALL 以密码学安全的随机数在多种任务类型、主题与措辞之间组合，生成长度不一的单轮或多轮对话，并在配置范围内随机选择输出 token 上限；任意两次生成的 prompt MUST NOT 含有可用于识别审计的固定标记。题库文件无法解析时代理 MUST 拒绝启动。

代理 SHALL 只发出 prompt token 数（按被审计模型的对话模板与分词，由代理自己的复核引擎计数）落在当前阈值版本的审计长度区间内的 prompt（`market/toploc`“复核判定规则与阈值”）：内置生成器的结果不在区间内时，代理 SHALL 重新生成或在不加入固定标记的前提下加长；题库中不在区间内的条目 SHALL 被跳过并计数（不含内容），题库中没有任何条目在区间内时代理 MUST 拒绝启动。代理 MUST NOT 为了凑长度在 prompt 中加入在所有审计 prompt 中重复出现的文字。

#### Scenario: prompt 多样
- **WHEN** 内置生成器连续生成 1,000 个 prompt
- **THEN** 其中互不相同的 prompt 至少 990 个，且没有任何长度不小于 16 个字符的子串出现在全部 prompt 中

#### Scenario: 题库无效
- **WHEN** 配置的题库文件不是有效的消息列表
- **THEN** 代理拒绝启动

#### Scenario: 审计 prompt 落在审计长度区间内
- **WHEN** 代理连续发出 200 个审计请求（内置生成器与题库混合）
- **THEN** 每个请求的 prompt token 数都在审计长度区间内，且“prompt 多样”的条件仍然成立

#### Scenario: 题库条目不在区间内
- **WHEN** 题库中一部分条目的 prompt token 数在审计长度区间之外
- **THEN** 这些条目从不被发出，代理记录被跳过的条目数；全部条目都在区间外时代理拒绝启动

### Requirement: 自动复核与提交裁决
审计请求完成后，代理 SHALL 按“复核一次推理”立即复核，并在本轮结束前提交裁决。由阈值判定的结果（通过，或某块超限的不通过）SHALL 附上该次复核的统计量与统计判定参数版本，并 SHALL 先把证据（`market/audit`“审计证据与承诺”）保存到数据目录，再提交带该证据承诺的裁决；其他“不通过”（缺少证明、证明与承诺不符、参数或块数不符）同样先保存证据再提交，不带统计量；无法判定直接提交，不带统计量与证据。裁决的阈值版本与统计判定参数版本 SHALL 等于收据所载模型在链上的审计档案中的版本；代理不认识档案中的任一版本时，代理 MUST NOT 提交裁决，并报告版本不符。提交失败时代理 SHALL 记录链返回的原因，本轮结束后不再重试。

#### Scenario: 作弊的提供者
- **WHEN** 被分配的提供者以另一模型的激活值交出证明
- **THEN** 代理在本轮内提交“不通过”裁决，链上记录的证据承诺等于数据目录中所存证据的承诺

#### Scenario: 诚实的提供者
- **WHEN** 被分配的提供者诚实服务
- **THEN** 代理在本轮内提交带统计量的“通过”裁决，链上记录的证据承诺等于数据目录中所存证据的承诺

#### Scenario: 无法判定不保存证据
- **WHEN** 复核结果为“无法判定（token 无法重现）”
- **THEN** 代理提交不带统计量与证据承诺的裁决，数据目录中不保存证据

#### Scenario: 按模型档案选版本
- **WHEN** 收据所载模型的档案为阈值版本 4、统计参数版本 1
- **THEN** 代理提交的裁决带阈值版本 4 与统计参数版本 1

#### Scenario: 统计参数版本不符
- **WHEN** 收据所载模型的档案中的统计判定参数版本是代理不认识的版本
- **THEN** 代理不提交裁决并报告版本不符

#### Scenario: 阈值版本不符
- **WHEN** 收据所载模型的档案中的阈值版本高于代理内置的版本
- **THEN** 代理不提交裁决并报告版本不符

### Requirement: 证据保存与交付
代理 SHALL 保存自己提交的每条带证据承诺的裁决的证据，直到同时满足：自提交起已过 2R + V 个区块（R 为轮次长度，V 为投票期限，此后它不能再被不通过争议或抽查引用）；它不在被审计提供者的任何统计判定参与列表中；引用它的争议与抽查都已关闭。之后删除。代理 SHALL 在登记的证据地址上经密封通道（`crypto/sealed-channel`）应答证据请求：请求给出争议或抽查的编号与证据承诺；代理 SHALL 按链上记录核对——请求方是该争议或抽查的复核人、它未关闭、本审计员的某条裁决被它引用（不通过争议的提出者、统计争议的参与裁决，或被抽查的裁决）、且所请求的承诺是该裁决所带的承诺——全部满足才交付证据字节，否则 SHALL 拒绝且不透露证据是否存在。代理日志中关于证据交付的记录 MUST 只包含争议或抽查编号、请求方账户与结果。

#### Scenario: 复核人取得证据
- **WHEN** 争议的复核人向提出者的证据地址索取该争议中的证据
- **THEN** 复核人收到证据，其承诺等于链上该裁决的证据承诺

#### Scenario: 统计争议的复核人取得证据
- **WHEN** 统计争议的复核人向一条“通过”的参与裁决的审计员索取其证据
- **THEN** 复核人收到证据，其承诺等于链上该裁决的证据承诺

#### Scenario: 抽查的复核人取得证据
- **WHEN** 抽查的复核人向被抽查裁决的审计员索取其证据
- **THEN** 复核人收到证据，其承诺等于链上该裁决的证据承诺

#### Scenario: 非复核人被拒绝
- **WHEN** 一个不是该争议或抽查复核人的账户索取证据
- **THEN** 代理拒绝，不返回任何证据内容

#### Scenario: 争议关闭后删除
- **WHEN** 引用某证据的争议与抽查都已关闭，该裁决提交后已过 2R + V 个区块，且不在参与列表中
- **THEN** 代理的数据目录中不再有该证据

#### Scenario: 累计归零后删除
- **WHEN** 一条“通过”裁决所在的累计值归零、它不再在参与列表中，提交后已过 2R + V 个区块，且没有争议或抽查引用它
- **THEN** 代理的数据目录中不再有该证据

#### Scenario: 抽查窗口内不删除
- **WHEN** 一条“通过”裁决提交后不足 2R + V 个区块，且它已不在参与列表中
- **THEN** 代理的数据目录中仍有该证据

### Requirement: 升级复核与投票
代理 SHALL 周期性地查询未关闭的争议，对本审计员被抽为复核人、尚未投票的每个争议投票，并在票中对争议记录的每条裁决标明是否取得了它的证据（取得证据、承诺相符且收据一致才算取得）。

不通过争议：向每名提出者的证据地址索取其裁决的证据，检查证据的承诺等于链上裁决的承诺、证据中的收据与链上裁决的收据一致，然后按裁决的阈值版本复核。至少两名不同提出者的证据复核结果为“不通过”时，代理 SHALL 投“确认”；否则（包括拿不到证据、承诺不符、收据不符、复核结果为通过或因证据本身无法判定）SHALL 投“驳回”。

统计争议：对每条参与裁决索取证据并做同样的检查，用本机复核引擎从证据重算统计量；检查不通过或拿不到证据的裁决，其贡献按不为正处理（正贡献去掉）；然后按争议记录的统计参数版本、以链上同样的规则重算累计值，达到判定界时 SHALL 投“确认”，否则 SHALL 投“驳回”。

本机复核引擎出错或不可用时，代理 SHALL 重试，到投票期限前仍不可用则 MUST NOT 投票并报告；代理不认识裁决的阈值版本或争议的统计参数版本时同样 MUST NOT 投票。

#### Scenario: 确认作弊
- **WHEN** 两名提出者对同一提供者的不通过裁决都基于真实的作弊证据，代理是该争议的复核人
- **THEN** 代理取得两份证据，复核都为不通过，投“确认”，两条裁决都标为取得证据

#### Scenario: 驳回伪造的不通过
- **WHEN** 提出者的证据复核结果为通过
- **THEN** 代理投“驳回”，该裁决标为取得证据

#### Scenario: 拿不到证据
- **WHEN** 提出者的证据地址在投票期限内一直无法连接
- **THEN** 代理投“驳回”，并把该提出者的裁决标为未取得证据

#### Scenario: 确认统计争议
- **WHEN** 统计争议的参与裁决来自一个以 int8 权重服务的提供者，代理是复核人
- **THEN** 代理从证据重算的累计值达到判定界，投“确认”

#### Scenario: 驳回虚报统计量
- **WHEN** 统计争议的参与裁决中，有审计员虚报了偏大的统计量，按证据重算后累计值低于判定界
- **THEN** 代理投“驳回”

#### Scenario: 本机引擎不可用
- **WHEN** 代理是复核人，但其复核引擎在整个投票期限内都不可用
- **THEN** 代理不投票，并报告引擎不可用

### Requirement: 审计付款账户
代理 SHALL 用配置的付款账户经透明额度通道为审计请求付费，规则与本地推理代理相同（逐请求校验收据与证明后签发累计凭证、已付总额持久化、重启后不重复付费、可选的花费上限）。代理 SHALL 在每个付款账户的通道余额不足或达到花费上限时停止使用该账户并报告；全部付款账户都不可用时，代理 SHALL 继续履行证据交付与投票，并报告无法发起审计请求。付款账户 MUST NOT 出现在任何裁决、投票或证据地址交易中。

#### Scenario: 付款账户耗尽
- **WHEN** 唯一的付款账户达到花费上限
- **THEN** 代理不再发起审计请求并报告，仍然应答证据请求并对争议投票

#### Scenario: 重启后不重复付费
- **WHEN** 代理用某付款账户完成若干审计请求后重启，再发起一个请求
- **THEN** 新凭证的累计金额等于重启前已付总额加上新请求的费用

### Requirement: 代理不记录内容
服务模式下，代理 MUST NOT 把审计 prompt、回答、证据内容或 token 写入日志；日志只允许包含轮次、提供者、网关、模型 ID、请求 ID、结果与原因、各块指标、统计量、交易哈希与计数。

#### Scenario: 日志中没有审计 prompt
- **WHEN** 用含唯一标记字符串的题库运行代理若干轮，并在调试日志级别下运行
- **THEN** 代理的日志中找不到该标记字符串，数据目录中只有带证据承诺的裁决的证据文件含有它

### Requirement: 抽查复核
代理 SHALL 周期性地查询未关闭的抽查（`market/audit`“裁决抽查”），对本审计员被抽为复核人、尚未投票的每个抽查投票：向被抽查裁决的审计员的证据地址索取证据，检查证据的承诺等于链上裁决的承诺、证据中的收据与链上裁决的收据一致，然后按裁决的阈值版本复核。复核结果与裁决相同时，代理 SHALL 投“维持”；否则（包括拿不到证据、承诺不符、收据不符）SHALL 投“推翻”。代理 MUST NOT 因统计量与自己重算的不同而投“推翻”。票中 SHALL 标明是否取得了证据。本机复核引擎不可用或不认识裁决的版本时，代理的处理与“升级复核与投票”相同。

#### Scenario: 维持诚实的裁决
- **WHEN** 代理是一次抽查的复核人，被抽查的“通过”裁决来自诚实服务的提供者
- **THEN** 代理复核结果为通过，投“维持”并标明取得了证据

#### Scenario: 推翻放水的裁决
- **WHEN** 被抽查的“通过”裁决的证据显示提供者换了模型
- **THEN** 代理复核结果为不通过，投“推翻”

#### Scenario: 拿不到证据
- **WHEN** 被抽查裁决的审计员的证据地址在投票期限内一直无法连接
- **THEN** 代理投“推翻”，并标明未取得证据

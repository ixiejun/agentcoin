# market/auditor-agent Specification

## Purpose
规定审计员代理（MVP 方案 §5.5、§7 的 `ac-auditor`）的行为。审计员只复核自己以普通用户身份发起的推理，用声明的模型在本地复算激活值，与提供者交来的 TOPLOC 证明比对并给出判定，使换模型、降精度或篡改 prompt 的提供者能被发现，而用户内容从不进入审计流程。本阶段覆盖“复核一次推理”；神秘顾客的发起、抽样与判定上链由后续变更加入。

## Requirements

### Requirement: 复核一次推理
审计员代理 SHALL 能复核一次已完成的推理。输入为：链上模型 ID 及其登记信息、请求的消息列表、提供者返回的输出文本与结束原因、返回的用量（输入与输出 token 数）、双签收据，以及随收据交回的 TOPLOC 证明（可以没有）。复核结果 SHALL 是以下三者之一：
- **通过**；
- **不通过**，原因为：没有证明、证明与收据承诺不符、证明参数或块数不符、或某块超出阈值（指明块序号与指标）；
- **无法判定**，原因为：模型登记的精度不受支持、无法重现 token、复核引擎出错或不可用。

复核前审计员代理 SHALL 检查收据中的模型、输入与输出 token 数与输入一致，不一致时结果为无法判定。

#### Scenario: 诚实提供者
- **WHEN** 提供者用登记的模型与 bfloat16 精度完成推理并交出证明，审计员复核
- **THEN** 结果为通过

#### Scenario: 换了模型
- **WHEN** 提供者用同架构的另一个模型完成推理并按其激活值交出证明，审计员按登记的模型复核
- **THEN** 结果为不通过，原因指明超出阈值的块

#### Scenario: 证明与承诺不符
- **WHEN** 交回的证明复算出的承诺与收据中的承诺不同
- **THEN** 结果为不通过，原因为证明与承诺不符

### Requirement: 缺少证明即不通过
审计员复核的收据若 TOPLOC 承诺为全零（没有证明），结果 SHALL 为“不通过（没有证明）”，无论原因是提供者未运行插件、插件未能交出完整候选还是其他情况。该规则只适用于审计员的复核；普通用户收据的有效性、付费与结算规则不因此改变。

#### Scenario: 全零承诺
- **WHEN** 审计员复核一张 TOPLOC 承诺为全零、没有证明的收据，且模型登记为 bfloat16
- **THEN** 结果为不通过，原因为没有证明

### Requirement: 只复核 bfloat16 模型
本阶段只有登记精度为 bfloat16 的模型接受 TOPLOC 复核。登记为其他精度的模型，复核结果 SHALL 为“无法判定（精度不支持）”，且 MUST NOT 被判为不通过（包括没有证明的情况）。

#### Scenario: int4 模型
- **WHEN** 审计员复核一次登记精度为 int4 的模型的推理
- **THEN** 结果为无法判定，原因为精度不支持

### Requirement: 重现 token
审计员代理 SHALL 用复核引擎、按登记模型的分词器与对话模板重现 token：prompt 的 token 由消息列表经对话模板得到；输出的 token 由输出文本分词得到。只有同时满足以下条件时才继续复算，否则结果 SHALL 为“无法判定（无法重现 token）”：
- prompt 的 token 数等于返回的输入 token 数；
- 输出的 token 解码后与输出文本完全相同；
- 结束原因为生成结束符时，输出文本的 token 数等于输出 token 数减 1；结束原因为达到长度上限时，等于输出 token 数；其他结束原因一律无法判定。

复算所用的序列 SHALL 为 prompt 的 token 后接输出的前“输出 token 数 − 1”个 token（最后一个生成的 token 不经过前向计算），复算结果按原推理的分块（prompt 为预填充，其后每个 token 为一个解码步骤）重组后与证明比对。

#### Scenario: token 数不符
- **WHEN** 输出文本重新分词后比收据的输出 token 数少 2 个
- **THEN** 结果为无法判定，原因为无法重现 token

#### Scenario: 因长度上限结束
- **WHEN** 一次推理因达到长度上限而结束，输出 40 个 token
- **THEN** 复算序列为 prompt 的 token 加输出的前 39 个 token，证明按 1 + ⌈39 / 32⌉ = 3 块比对

### Requirement: 复核不记录内容
审计员代理 MUST NOT 把复核所用的消息、输出文本、token 或激活值候选写入日志；日志只允许包含请求 ID、模型 ID、计数、各块指标与判定结果。

#### Scenario: 日志中没有内容
- **WHEN** 用含唯一标记字符串的消息完成一次复核，并在调试日志级别下运行
- **THEN** 审计员代理与复核引擎的日志中找不到该标记字符串

### Requirement: 审计证据
审计员代理 SHALL 能把一次复核的输入（请求的 messages、回答文本、结束原因、用量、双签收据与 TOPLOC 证明）导出为 `market/audit`“审计证据与承诺”规定的证据编码，并给出其承诺，供提交“不通过”裁决。审计员代理 SHALL 能从一份证据与链上记录的承诺复核：先检查证据的承诺等于给定承诺，不相等时结果为“证据与承诺不符”，不进行复核；相等时按“复核一次推理”复核，结果与从原案例复核相同。导出与复核都 MUST NOT 把证据内容写入日志。

#### Scenario: 导出再复核
- **WHEN** 把一次判为“不通过”的复核案例导出为证据，再以导出的承诺从证据复核
- **THEN** 结果仍为“不通过”，原因与原复核相同

#### Scenario: 承诺不符
- **WHEN** 以一个与证据不符的承诺从证据复核
- **THEN** 结果为“证据与承诺不符”，不调用复核引擎

# market/engine-plugin Specification

## Purpose
规定推理引擎（vLLM）内的 TOPLOC 激活值采集插件：在什么前提下加载、从每个请求的前向计算中取出哪些激活值候选、以什么本机协议交给提供者代理，以及它必须遵守的隐私与失败行为，使提供者能为每个请求构造与参考实现一致的 TOPLOC 证明。

## Requirements

### Requirement: 加载前提
插件 SHALL 以引擎的标准插件机制加载，只有在配置了提供者的本机套接字地址时才启用；未配置时 MUST 不改变引擎的任何行为。启用时插件 SHALL 检查以下前提，任一不满足 MUST 使引擎启动失败并说明原因，而不是静默地不产生证明：
- 引擎版本在插件声明支持的范围内；
- 模型以 bfloat16 运行；
- 前缀缓存与投机解码关闭（二者会让部分 token 不经过前向计算或经过多次）；
- 不使用流水线并行。

使用张量并行时，只有持有完整最终输出的一个工作进程发送候选。

#### Scenario: 未配置时不生效
- **WHEN** 安装插件但不配置套接字地址，启动引擎并完成一个请求
- **THEN** 引擎正常服务，插件不建立任何连接

#### Scenario: 前缀缓存开启时拒绝启动
- **WHEN** 配置了套接字地址并开启前缀缓存启动引擎
- **THEN** 引擎启动失败，错误说明需要关闭前缀缓存

#### Scenario: 非 bfloat16 时拒绝启动
- **WHEN** 配置了套接字地址并以 float16 精度启动引擎
- **THEN** 引擎启动失败，错误说明只支持 bfloat16

### Requirement: 每段激活的 top-k 候选
对每个前向步骤中的每个请求，插件 SHALL 取该请求在本步中计算的 token 在模型最终归一化层的输出（与参考实现所取的激活值相同），按行展平为一段；预填充被分成多步时，每步各为一段。对每段，插件 SHALL 按“绝对值降序、绝对值相等时下标升序”的顺序取前 k 个元素（段内元素少于 k 时取全部），与 `market/toploc` 构造证明的顺序相同，因此第 k 名处出现并列时选下标较小者；记下它们在段内的下标与原始 bfloat16 编码，连同段的元素总数与阶段（预填充或解码）发给提供者；k 由提供者在连接时告知。候选值 MUST 与该步实际计算出的激活值逐位相同。请求完成或中止时，插件 SHALL 发送该请求的结束标记。

#### Scenario: 候选与激活值一致
- **WHEN** 用单个请求运行引擎，同时用独立的钩子记录最终归一化层的全部输出
- **THEN** 插件为每段发送的候选恰好是该段激活值按绝对值排序的前 k 项，下标与编码逐位相同

#### Scenario: 第 k 名处的并列
- **WHEN** 一段激活中第 k 大与第 k+1 大的绝对值相等
- **THEN** 插件发送的候选包含其中下标较小的那个，由这些候选构造的证明与由该请求全量激活值构造的证明逐字节相同

#### Scenario: 分步预填充
- **WHEN** 一个长 prompt 的预填充被引擎分成 3 步计算
- **THEN** 插件为该请求发送 3 段预填充候选，各段元素总数之和等于 prompt token 数乘以隐藏维度

#### Scenario: 结束标记
- **WHEN** 请求生成完毕或被客户端中止
- **THEN** 插件为该请求发送结束标记，且之后不再发送该请求的候选

### Requirement: 与提供者的本机协议
插件与接收方（提供者，或审计员的复核程序）之间 SHALL 只经本机 Unix 套接字通信：接收方监听，插件连接；连接建立时插件声明协议版本、隐藏维度与模式（证明或复核），接收方回复协议版本与 k。提供者 MUST 只接受证明模式，审计员的复核程序 MUST 只接受复核模式；模式不符时接收方 MUST 断开连接，插件 SHALL 记录一次模式不符并停止发送。每条消息 SHALL 带引擎内部的请求 ID，接收方据此与自己提交的请求对应（接收方提交请求时带上请求 ID，引擎内部 ID 包含它）。协议版本不符时 MUST 断开连接且插件不再发送。接收方不可达或连接断开时，插件 SHALL 丢弃候选并定期重连，MUST NOT 阻塞或拖慢推理。

#### Scenario: 提供者不在线
- **WHEN** 引擎运行期间提供者进程退出
- **THEN** 引擎继续正常服务，提供者重新启动后插件重新连接并恢复发送

#### Scenario: 版本不符
- **WHEN** 提供者声明的协议版本与插件不同
- **THEN** 连接被断开，引擎继续服务，插件记录一次版本不符

#### Scenario: 提供者拒绝复核模式
- **WHEN** 以复核模式运行的插件连接到提供者的套接字
- **THEN** 提供者断开连接，不为任何请求使用这些候选构造证明

#### Scenario: 复核程序拒绝证明模式
- **WHEN** 以证明模式运行的插件连接到审计员复核程序的套接字
- **THEN** 复核程序断开连接，复核不使用这些候选

### Requirement: 插件不记录内容
插件 MUST NOT 把 prompt、输出、token、激活值或候选写入日志、磁盘或除本机提供者套接字之外的任何地方；日志只允许包含连接状态、请求 ID 与计数。

#### Scenario: 日志中没有内容
- **WHEN** 用含唯一标记字符串的 prompt 完成一个请求，并在调试日志级别下运行
- **THEN** 引擎日志中找不到该标记字符串，插件没有写入任何文件

### Requirement: 复核模式
插件 SHALL 支持两种模式：**证明**（默认，提供者使用）与**复核**（审计员使用），由引擎启动时的配置选择；两种模式适用相同的加载前提。复核模式下，引擎只用于对“prompt + 已知输出”做预填充：插件 SHALL 对每个请求预填充中计算的**每个 token 行**各发送一段候选（段的元素总数等于隐藏维度，阶段为预填充，候选的选取顺序与证明模式相同），并按 token 在请求中的位置顺序发送；预填充被引擎分成多步时，各步的行依次发送。复核模式下插件 MUST NOT 为解码步骤发送候选。请求完成或中止时插件 SHALL 发送结束标记。

#### Scenario: 每个 token 一段
- **WHEN** 复核模式下提交一个 100 个 token 的 prompt、最多生成 1 个 token
- **THEN** 插件为该请求发送 100 段候选，每段元素总数等于隐藏维度，随后发送结束标记

#### Scenario: 与证明模式的激活一致
- **WHEN** 证明模式下的引擎为一次推理产生了激活值，复核模式下用同一模型对“prompt + 输出（除最后一个 token）”预填充
- **THEN** 在同一硬件与精度下，复核得到的每行候选与证明模式中对应位置的激活值按同一顺序取出的前 k 项数值接近，用它们比对原证明时每块都在阈值内

#### Scenario: 分步预填充
- **WHEN** 复核模式下一个长序列的预填充被引擎分成 3 步计算
- **THEN** 插件发送的段数仍等于序列的 token 数，顺序与 token 位置一致

### Requirement: CPU 复核的指令集
复核阈值只在 CPU 不使用 AMX 矩阵指令的条件下校准过。插件处于复核模式、模型在 CPU 上运行且该 CPU 支持 AMX 时，SHALL 要求引擎已把 CPU 数学库的最高指令集限制在 AMX 以下，否则 MUST 拒绝加载模型并说明所需的设置。证明模式、GPU 上的复核以及不支持 AMX 的 CPU 不受此限制。

#### Scenario: AMX CPU 上未关闭 AMX
- **WHEN** 在支持 AMX 的 CPU 上以复核模式启动引擎，且没有限制最高指令集
- **THEN** 引擎拒绝启动，错误信息给出所需的设置

#### Scenario: 关闭 AMX 后正常复核
- **WHEN** 在同一 CPU 上把最高指令集限制为 AVX-512 BF16 后以复核模式启动
- **THEN** 引擎正常启动

# market/engine-plugin Specification

## Purpose
规定推理引擎（vLLM）内的 TOPLOC 激活值采集插件：在什么前提下加载、从每个请求的前向计算中取出哪些激活值候选、以什么本机协议交给提供者代理，以及它必须遵守的隐私与失败行为，使提供者能为每个请求构造与参考实现一致的 TOPLOC 证明。

## Requirements

### Requirement: 加载前提
插件 SHALL 以引擎的标准插件机制加载，只有在配置了提供者的本机套接字地址时才启用；未配置时 MUST 不改变引擎的任何行为。启用时插件 SHALL 检查以下前提，任一不满足 MUST 使引擎启动失败并说明原因，而不是静默地不产生证明：
- 引擎版本在插件声明支持的范围内；
- 模型以 bfloat16 运行；
- 前缀缓存与投机解码关闭（二者会让部分 token 不经过前向计算或经过多次）；
- 不使用流水线并行。

使用张量并行时，只有持有完整最终输出的一个工作进程发送候选。

#### Scenario: 未配置时不生效
- **WHEN** 安装插件但不配置套接字地址，启动引擎并完成一个请求
- **THEN** 引擎正常服务，插件不建立任何连接

#### Scenario: 前缀缓存开启时拒绝启动
- **WHEN** 配置了套接字地址并开启前缀缓存启动引擎
- **THEN** 引擎启动失败，错误说明需要关闭前缀缓存

#### Scenario: 非 bfloat16 时拒绝启动
- **WHEN** 配置了套接字地址并以 float16 精度启动引擎
- **THEN** 引擎启动失败，错误说明只支持 bfloat16

### Requirement: 每段激活的 top-k 候选
对每个前向步骤中的每个请求，插件 SHALL 取该请求在本步中计算的 token 在模型最终归一化层的输出（与参考实现所取的激活值相同），按行展平为一段；预填充被分成多步时，每步各为一段。对每段，插件 SHALL 按“绝对值降序、绝对值相等时下标升序”的顺序取前 k 个元素（段内元素少于 k 时取全部），与 `market/toploc` 构造证明的顺序相同，因此第 k 名处出现并列时选下标较小者；记下它们在段内的下标与原始 bfloat16 编码，连同段的元素总数与阶段（预填充或解码）发给提供者；k 由提供者在连接时告知。候选值 MUST 与该步实际计算出的激活值逐位相同。请求完成或中止时，插件 SHALL 发送该请求的结束标记。

#### Scenario: 候选与激活值一致
- **WHEN** 用单个请求运行引擎，同时用独立的钩子记录最终归一化层的全部输出
- **THEN** 插件为每段发送的候选恰好是该段激活值按绝对值排序的前 k 项，下标与编码逐位相同

#### Scenario: 第 k 名处的并列
- **WHEN** 一段激活中第 k 大与第 k+1 大的绝对值相等
- **THEN** 插件发送的候选包含其中下标较小的那个，由这些候选构造的证明与由该请求全量激活值构造的证明逐字节相同

#### Scenario: 分步预填充
- **WHEN** 一个长 prompt 的预填充被引擎分成 3 步计算
- **THEN** 插件为该请求发送 3 段预填充候选，各段元素总数之和等于 prompt token 数乘以隐藏维度

#### Scenario: 结束标记
- **WHEN** 请求生成完毕或被客户端中止
- **THEN** 插件为该请求发送结束标记，且之后不再发送该请求的候选

### Requirement: 与提供者的本机协议
插件与提供者之间 SHALL 只经本机 Unix 套接字通信：提供者监听，插件连接；连接建立时双方交换协议版本，提供者告知 k。每条消息 SHALL 带引擎内部的请求 ID，提供者据此与自己转发的请求对应（提供者转发时带上请求 ID，引擎内部 ID 包含它）。协议版本不符时 MUST 断开连接且插件不再发送。提供者不可达或连接断开时，插件 SHALL 丢弃候选并定期重连，MUST NOT 阻塞或拖慢推理。

#### Scenario: 提供者不在线
- **WHEN** 引擎运行期间提供者进程退出
- **THEN** 引擎继续正常服务，提供者重新启动后插件重新连接并恢复发送

#### Scenario: 版本不符
- **WHEN** 提供者声明的协议版本与插件不同
- **THEN** 连接被断开，引擎继续服务，插件记录一次版本不符

### Requirement: 插件不记录内容
插件 MUST NOT 把 prompt、输出、token、激活值或候选写入日志、磁盘或除本机提供者套接字之外的任何地方；日志只允许包含连接状态、请求 ID 与计数。

#### Scenario: 日志中没有内容
- **WHEN** 用含唯一标记字符串的 prompt 完成一个请求，并在调试日志级别下运行
- **THEN** 引擎日志中找不到该标记字符串，插件没有写入任何文件

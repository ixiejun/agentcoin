# chain/state-hashing Specification

## Purpose
规定 AgentCoin 链的区块头、外部交易根和状态树统一使用 BLAKE3-256，并界定存储键哈希器这一有界例外，保证链上承诺全部为 256 位抗量子哈希（D35）。

## Requirements

### Requirement: 区块与状态承诺使用 BLAKE3-256
链上所有完整性承诺 SHALL 使用 32 字节的 BLAKE3 输出，包括：区块头哈希（即区块 ID）、父区块引用、外部交易根、状态根，以及状态证明中的节点哈希。上述承诺 MUST NOT 使用 BLAKE2、Twox、Keccak 或任何输出短于 256 位的哈希。

#### Scenario: 区块哈希可独立复算
- **WHEN** 取任意已导入区块的 SCALE 编码区块头，用 BLAKE3（普通哈希模式，32 字节输出）独立计算哈希
- **THEN** 结果与节点报告的该区块哈希逐字节相同

#### Scenario: 状态根可独立复算
- **WHEN** 对一个只含已知键值对的创世状态，用 BLAKE3 作为节点哈希、按链的状态树格式独立计算根
- **THEN** 结果与创世区块头中的状态根相同

#### Scenario: 外部交易根可独立复算
- **WHEN** 对某区块内的全部外部交易，用 BLAKE3 按链的有序树格式计算根
- **THEN** 结果与该区块头中的外部交易根相同

### Requirement: 存储键哈希器的有界例外
用于排列存储键、不承担完整性或唯一性承诺的键哈希器（例如 SDK 自带模块使用的 128 位键哈希）SHALL 作为已记录的例外保留；本项目自有模块中，以账户 ID 或其他已是 256 位哈希输出的值为键的存储映射 MUST 直接使用原值作为键（不再做短哈希），并 MUST NOT 以任何短于 256 位的哈希结果作为安全判断的依据。

#### Scenario: 自有模块的账户键
- **WHEN** 读取公钥登记表中某账户对应的原始存储键
- **THEN** 键的末尾 32 字节等于该账户 ID 本身

### Requirement: 哈希方案随创世固定
链的哈希方案 SHALL 在创世时固定，并通过公开的 runtime API 对外声明；任何更换 MUST 作为新链或硬分叉处理，不能通过普通 runtime 升级完成。

#### Scenario: 哈希方案标识可查询
- **WHEN** 客户端通过 runtime API 查询链的密码学配置
- **THEN** 返回的区块与状态哈希算法为 BLAKE3-256

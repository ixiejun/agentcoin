# consensus/validator-set Specification

## Purpose
规定链的纪元划分、授权节点集合及其编号，以及集合只在纪元边界变更并通过区块头摘要通告的规则，使出块与终局性投票始终使用同一份、可追溯的验证人名单。

## Requirements

### Requirement: 纪元划分
链 SHALL 按固定区块数把区块划分为纪元：纪元长度 L 由创世配置给出，创世之后不可更改，且 MUST 不小于创世授权节点数的 2 倍（M2 中集合只会缩小，该下限始终成立），使每个验证人在每个纪元内都有多个出块时隙。高度为 b（b ≥ 1）的区块属于纪元 ⌊(b − 1) / L⌋；每个纪元的第一个区块称为纪元边界区块。纪元长度不合规的创世配置 MUST 构建失败。

#### Scenario: 纪元编号
- **WHEN** 纪元长度为 20 时查询高度 1、20、21 的区块所属纪元
- **THEN** 分别为纪元 0、0、1，其中高度 21 是纪元边界区块

#### Scenario: 纪元过短
- **WHEN** 用 4 个授权节点、纪元长度为 7 的创世配置构建链规格
- **THEN** 构建失败并报告纪元长度不合规

### Requirement: 授权节点集合与编号
链 SHALL 维护当前授权节点集合（ML-DSA-65 公钥的有序列表，每个成员带权重，PoA 阶段权重固定为 1）和集合编号：创世集合编号为 0，每次变更加 1。出块时隙分配和 AC-BFT 投票 MUST 使用同一份集合。当前集合、集合编号和纪元长度 SHALL 可以通过 runtime API 查询；链 MUST 保留最近若干个纪元的历史集合，供证据验证使用。

#### Scenario: 查询集合
- **WHEN** 查询 `local` 链创世后的授权节点集合
- **THEN** 返回编号 0 和 4 个 ML-DSA-65 公钥，顺序与创世配置一致，权重均为 1

### Requirement: 只在纪元边界变更并通告
授权节点集合 SHALL 只在纪元边界区块变更，M2 中唯一的变更原因是移除被禁用的验证人。发生变更时，纪元边界区块的区块头 MUST 包含一条集合变更摘要（新集合编号和完整的新成员列表），从该区块之后的区块起按新集合分配出块时隙；没有变更的边界区块 MUST NOT 包含集合变更摘要。

#### Scenario: 变更摘要
- **WHEN** 纪元 e 内有一个验证人被禁用
- **THEN** 纪元 e+1 的边界区块头包含新集合编号和去掉该验证人后的成员列表，下一个区块的出块人按新列表确定

#### Scenario: 无变更无摘要
- **WHEN** 纪元内没有任何违规
- **THEN** 下一纪元的边界区块头不包含集合变更摘要，集合编号不变

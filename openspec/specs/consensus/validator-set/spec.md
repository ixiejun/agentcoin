# consensus/validator-set Specification

## Purpose
规定链的纪元划分、授权节点集合及其编号，以及集合只在纪元边界变更并通过区块头摘要通告的规则，使出块与终局性投票始终使用同一份、可追溯的验证人名单。

## Requirements

### Requirement: 纪元划分
链 SHALL 按固定区块数把区块划分为纪元：纪元长度 L 由创世配置给出，创世之后不可更改，且 MUST 不小于集合规模上限（PoS 活跃集合规模 K 与 PoA 集合当前成员数中的较大者）的 2 倍，使每个验证人在每个纪元内都有多个出块时隙；把 K 调到超过 L/2 或使 PoA 集合超过 L/2 个成员的操作 MUST 被拒绝。高度为 b（b ≥ 1）的区块属于纪元 ⌊(b − 1) / L⌋；每个纪元的第一个区块称为纪元边界区块。纪元长度不合规的创世配置 MUST 构建失败。

#### Scenario: 纪元编号
- **WHEN** 纪元长度为 20 时查询高度 1、20、21 的区块所属纪元
- **THEN** 分别为纪元 0、0、1，其中高度 21 是纪元边界区块

#### Scenario: 纪元过短
- **WHEN** 用 4 个授权节点、纪元长度为 7 的创世配置构建链规格
- **THEN** 构建失败并报告纪元长度不合规

#### Scenario: 集合规模超过纪元长度一半
- **WHEN** 纪元长度为 20 时尝试把活跃集合规模 K 设为 11
- **THEN** 操作被拒绝，K 不变

### Requirement: 授权节点集合与编号
链 SHALL 维护当前授权节点集合（ML-DSA-65 公钥的有序列表，每个成员带权重）和集合编号：创世集合编号为 0，每次变更加 1。PoA 阶段每个成员的权重 MUST 为 1；PoS 阶段成员权重 MUST 按选举得到的支撑额确定（见 `consensus/npos-election`）。出块时隙分配和 AC-BFT 投票 MUST 使用同一份集合：出块时隙按成员顺序轮流分配，与权重无关；AC-BFT 按权重计票。当前集合、集合编号、纪元长度和当前阶段 SHALL 可以通过 runtime API 查询；链 MUST 保留最近若干个纪元的历史集合，供证据验证使用。

#### Scenario: 查询集合
- **WHEN** 查询 `local` 链创世后的授权节点集合
- **THEN** 返回编号 0 和 4 个 ML-DSA-65 公钥，顺序与创世配置一致，权重均为 1

#### Scenario: PoS 阶段的权重
- **WHEN** 切换到 PoS 后查询授权节点集合
- **THEN** 每个成员的权重与其选举支撑额成比例

### Requirement: 只在纪元边界变更并通告
授权节点集合 SHALL 只在纪元边界区块变更。变更原因为：PoA 阶段由管理权限增删 PoA 授权节点、移除被禁用的验证人；PoS 阶段新的选举结果（其中不含被禁用或暂停参选的验证人）；以及切换到 PoS 的那一次替换。发生变更时，纪元边界区块的区块头 MUST 包含一条集合变更摘要（新集合编号和完整的新成员列表及权重），从该区块之后的区块起按新集合分配出块时隙；没有变更的边界区块 MUST NOT 包含集合变更摘要。集合 MUST 始终非空。

#### Scenario: 变更摘要
- **WHEN** 纪元 e 内有一个验证人被禁用
- **THEN** 纪元 e+1 的边界区块头包含新集合编号和去掉该验证人后的成员列表，下一个区块的出块人按新列表确定

#### Scenario: 无变更无摘要
- **WHEN** 纪元内没有任何违规、没有增删、选举结果与当前集合完全相同
- **THEN** 下一纪元的边界区块头不包含集合变更摘要，集合编号不变

#### Scenario: 选举结果变化
- **WHEN** PoS 阶段一次选举的当选者或权重与当前集合不同
- **THEN** 下一纪元边界区块头包含新集合的摘要，集合编号加 1

# node/chain-spec Specification

## Purpose
规定节点客户端的开发与本地链规格、正式链创世零发行检查（D9，由节点强制）、验证人密钥加载方式以及三节点本地网络。

## Requirements

### Requirement: 开发与本地链规格
节点 SHALL 内置两个开发链规格：`dev`（1 个授权节点，可单机出块）与 `local`（3 个授权节点）。二者的链类型 MUST 标记为开发 / 本地类型，授权节点与预置账户 MUST 使用公开的、由固定名称确定性派生的开发密钥，且 MUST 在链名中明确标注为开发用途。

#### Scenario: 单节点开发链出块
- **WHEN** 以 `dev` 链规格启动单个节点
- **THEN** 节点在 10 秒内产出至少 5 个区块

#### Scenario: 开发密钥可复现
- **WHEN** 两次由同一开发名称（例如 `alice`）派生开发密钥
- **THEN** 两次得到相同的 ML-DSA 公钥与账户 ID

### Requirement: 正式链创世零发行
只有开发 / 本地类型的链规格 SHALL 可以在创世中分配余额。节点在启动时 MUST 检查链规格：若链类型为正式链（live）且创世状态中的总发行量不为零，或任一账户余额不为零，节点 MUST 拒绝启动并给出明确错误（D9 无预挖）。该检查 MUST 在节点客户端中实现，不依赖 runtime 的配合。

#### Scenario: 带预挖的正式链规格
- **WHEN** 以一个链类型为正式链、创世给某账户分配了 1 ATC 的链规格启动节点
- **THEN** 节点拒绝启动，错误信息指出违反“创世零发行”

#### Scenario: 零发行的正式链规格
- **WHEN** 以一个链类型为正式链、创世无任何余额分配的链规格启动节点
- **THEN** 节点通过该项检查

#### Scenario: 内置非开发预设为零发行
- **WHEN** 枚举 runtime 提供的全部创世预设
- **THEN** 除开发 / 本地预设之外，所有预设的总发行量都为零

### Requirement: 验证人密钥加载
授权节点 SHALL 支持两种出块密钥来源：(a) 加密密钥文件加口令文件；(b) 仅在开发 / 本地链上可用的开发密钥名称。在正式链上指定开发密钥 MUST 使节点拒绝启动；密钥文件口令错误或文件被篡改时 MUST 拒绝启动且不泄露任何密钥信息。

#### Scenario: 正式链上使用开发密钥
- **WHEN** 以正式链类型的链规格并指定开发密钥 `alice` 启动节点
- **THEN** 节点拒绝启动

#### Scenario: 口令错误
- **WHEN** 以错误口令加载加密出块密钥文件启动节点
- **THEN** 节点拒绝启动，错误信息只说明“解密失败”

### Requirement: 三节点本地网络
使用 `local` 链规格的 3 个节点 SHALL 能在同一台机器上互相发现（通过引导节点地址）并持续出块。

#### Scenario: 三节点持续出块
- **WHEN** 在本机以 `local` 链规格启动 3 个授权节点并运行 60 秒
- **THEN** 三个节点的最佳区块高度都不低于 40，且在同一高度上的区块哈希一致（允许最新 3 个区块内的短暂分叉）

#### Scenario: 节点重启后追上
- **WHEN** 停止其中一个节点 20 秒后重新启动
- **THEN** 它在 30 秒内同步到与其余节点相差不超过 3 个区块的高度

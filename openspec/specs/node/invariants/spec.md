# node/invariants Specification

## Purpose
规定节点客户端强制执行的宪法第 1 层检查：总量上限、铸币只能来自排放结算且受排放曲线约束、无预挖。检查只依赖已发布的固定存储键与链规格的创世参数，任何 runtime 升级都不能绕过；违反即拒绝区块。

## Requirements

### Requirement: 总量上限
节点 SHALL 在导入每个区块后检查总发行量不超过 21,000,000 ATC；超过时 MUST 拒绝该区块。

#### Scenario: 超过总量
- **WHEN** 某区块执行后总发行量超过 21,000,000 ATC
- **THEN** 节点拒绝该区块，并在日志中指出违反“总量上限”

### Requirement: 铸币受排放曲线约束
节点 SHALL 按“铸币量 = 总发行量变化 + 累计销毁量变化”计算每个区块的铸币量，并检查：非排放结算区块的铸币量 MUST 不大于 0；排放结算区块的铸币量 MUST 不超过上一纪元计划量的 2 倍；自创世起的累计铸币量（当前总发行量 + 累计销毁量 − 创世总发行量）MUST 不超过截至上一纪元的累计计划量。计划量按链规格中的创世纪元长度计算。任一检查失败时 MUST 拒绝该区块。

#### Scenario: 非结算区块铸币
- **WHEN** 某个不是排放结算的区块使总发行量加累计销毁量增加了 1 个最小单位
- **THEN** 节点拒绝该区块，日志指出违反“铸币受排放曲线约束”

#### Scenario: 正常排放
- **WHEN** 诚实的 runtime 连续结算多个纪元
- **THEN** 节点接受全部区块

### Requirement: 规则不受 runtime 升级影响
节点不变量 SHALL 只读取已发布的固定存储键（总发行量、累计销毁量）和链规格的创世参数（排放纪元长度、创世总发行量），不调用 runtime 获取判断依据。固定存储键缺失或无法解码时 MUST 拒绝该区块（fail-closed）。更改这些规则 MUST 发布新的节点客户端（硬分叉）。

#### Scenario: 超发的 runtime 升级
- **WHEN** 在开发链上由管理权限把 runtime 升级为一个在排放结算时多铸币的版本
- **THEN** 多铸币的区块被节点拒绝，链不再在该分支上前进，日志指出违反的规则

#### Scenario: 固定存储键被移除
- **WHEN** 某区块执行后累计销毁量的固定存储键不存在
- **THEN** 节点拒绝该区块

### Requirement: 对所有区块同样检查
节点 SHALL 对从网络导入的区块、同步得到的区块和自己产出的区块执行同样的检查；自己产出的区块违反规则时 MUST 不导入也不广播。

#### Scenario: 本节点产出违规区块
- **WHEN** 本节点在已被升级为超发版本的 runtime 上产出结算区块
- **THEN** 该区块不被导入、不被广播

### Requirement: 启动时校验创世参数
节点 SHALL 在启动时从链规格读取排放纪元长度和创世总发行量，并检查纪元长度能整除 126,230,400；不满足时 MUST 拒绝启动。正式链的创世零发行检查（D9）MUST 同样在该模块中执行。

#### Scenario: 链规格缺少纪元长度
- **WHEN** 以缺少排放纪元长度的链规格启动节点
- **THEN** 节点拒绝启动并给出明确错误

# clients/wallet-cli Specification

## Purpose
规定命令行钱包的对外行为：用 24 个助记词创建或导入钱包、钱包文件只保存口令加密后的秘密、以 atc1 地址显示账户、通过节点 RPC 查询余额、发起 ML-DSA 签名的转账以及在地址不变的前提下轮换密钥。

## Requirements

### Requirement: 创建与导入钱包
命令行钱包 SHALL 能新建钱包（生成随机种子熵并显示 24 个助记词一次）和从助记词导入钱包；钱包文件 MUST 使用 `crypto/key-storage` 的加密格式保存，口令从交互式输入或显式指定的口令文件读取，MUST NOT 从命令行参数读取。新建账户的默认签名算法为 ML-DSA-44，并可指定 ML-DSA-65 / ML-DSA-87。

#### Scenario: 新建后可导入
- **WHEN** 新建钱包并记下助记词，再在另一个目录用该助记词导入
- **THEN** 两个钱包显示相同的账户地址

#### Scenario: 钱包文件无明文
- **WHEN** 新建钱包后检查钱包文件内容
- **THEN** 文件中不包含种子熵或助记词的明文

### Requirement: 地址显示
钱包 SHALL 显示账户 ID 的规范文本形式（带校验的编码，编码规则在设计中固定并有测试向量），并 SHALL 能把该文本形式解析回账户 ID；校验失败的地址 MUST 被拒绝。

#### Scenario: 地址往返
- **WHEN** 把账户 ID 编码为地址文本再解析
- **THEN** 得到相同的账户 ID

#### Scenario: 地址输错
- **WHEN** 输入一个改动了一个字符的地址作为转账目标
- **THEN** 钱包拒绝并提示地址校验失败，不提交任何交易

### Requirement: 查询与转账
钱包 SHALL 能通过节点 RPC 查询任一账户的余额、nonce 与登记状态，并能构造、签名、提交转账交易，报告交易被纳入的区块哈希或失败原因。账户未登记公钥时，钱包 MUST 自动在交易中携带公钥。

#### Scenario: 首次转账
- **WHEN** 用新钱包（已收到开发账户转入的资金、尚未登记）向另一地址转账
- **THEN** 钱包报告交易已上链，目标账户余额相应增加，本账户变为已登记

### Requirement: 密钥轮换
钱包 SHALL 提供轮换命令：在本地生成（或由助记词按下一个序号派生）新密钥，构造并提交 `rotate_key` 交易，成功后更新钱包文件中的当前密钥并保留账户 ID。

#### Scenario: 轮换后继续使用
- **WHEN** 通过钱包轮换密钥后再转账
- **THEN** 转账成功，发送方地址与轮换前相同

### Requirement: 钱包作为 EVM 外部签名器
钱包 SHALL 提供 `evm` 子命令组，用账户的 ML-DSA 密钥为合约交易签名，并通过节点 RPC 或 eth-RPC 适配器提交：
- `address`：显示账户的 20 字节 EVM 地址（带 EIP-55 大小写校验）；
- `deploy`：读取 Foundry 编译产物（JSON）中的初始化字节码，附加 ABI 编码的构造参数后部署，报告交易哈希、区块和新合约地址；
- `send`：以合约地址、calldata（或函数签名加参数）与可选金额发起调用，报告交易哈希、区块、成功或回滚；
- `broadcast`：读取 `forge script` 的模拟输出（`run-latest.json`），按顺序把每笔交易转换为原生合约交易、签名并提交，每笔等到被打包后再发下一笔；
- `sign-message`：以上下文 `agentcoin/evm-verify/v1` 对消息签名，输出 AlgId、公钥与签名，供合约中的 `pq_verify` 使用；
- `raw`：只签名不提交，输出可交给 `eth_sendRawTransaction` 的交易字节。

钱包 SHALL 在发送前用只读查询估算权重与存储押金，按设计固定的余量设置上限。只读查询显示调用会回滚时，钱包 MUST 不提交并报告回滚原因，除非用户显式要求强制提交。

#### Scenario: 部署 ERC-20
- **WHEN** 对 `forge build` 生成的 ERC-20 产物执行 `ac-wallet evm deploy`，并附带名称、符号和初始供应量
- **THEN** 输出新合约地址；用 `cast call` 经适配器查询部署者余额，得到初始供应量

#### Scenario: 回滚的调用不提交
- **WHEN** 对一个余额不足的 ERC-20 转账执行 `ac-wallet evm send`
- **THEN** 钱包报告回滚原因，不提交交易，账户 nonce 不变

#### Scenario: broadcast 地址不一致时中止
- **WHEN** `run-latest.json` 中某笔部署的预测合约地址与链上实际创建的地址不同
- **THEN** 钱包在该笔之后立即停止，报告两者地址，不再发送后续交易

#### Scenario: 签名供 pq_verify 使用
- **WHEN** 用 `ac-wallet evm sign-message` 签名一段消息，并把输出传给调用 `pq_verify` 的合约
- **THEN** 合约得到 `true`

#### Scenario: raw 交易可经适配器提交
- **WHEN** 把 `ac-wallet evm raw` 的输出传给适配器的 `eth_sendRawTransaction`
- **THEN** 交易被打包，返回的哈希与钱包显示的哈希一致

### Requirement: 市场子命令
钱包 SHALL 提供 `market` 子命令组，用账户的 ML-DSA 密钥签名并通过节点 RPC 提交市场交易、查询市场状态：
- 模型：从清单文件登记模型，并在提交前于本地计算、显示模型 ID；查询模型。
- 提供者：登记、修改地址/加密公钥/价格、心跳、追加与减少质押、退出、取回解绑的质押；查询单个提供者与某模型的可服务提供者。
- 网关：登记、修改地址与费率、追加与减少质押、退出、取回；查询网关。
- 托管：向网关托管、申请取回、取回、申请更换凭证密钥；查询通道。
- 凭证：按给定网关与累计授权额（美元）签发凭证，输出凭证编码（供测试与 SDK 对照）；对一张凭证按链上当前状态做链下校验并显示结论。
- 汇率：查询当前参考汇率与设置高度。

美元金额以十进制美元输入（最多 6 位小数），ATC 金额沿用现有的金额格式；输入超出范围或格式错误时 MUST 在提交前报错。交易失败时 MUST 显示链上返回的错误名称。

#### Scenario: 本地模型 ID 与链上一致
- **WHEN** 用钱包从清单文件登记模型
- **THEN** 钱包提交前显示的模型 ID 与登记成功后链上记录的模型 ID 相同

#### Scenario: 签发并校验凭证
- **WHEN** 用户托管后用钱包签发一张累计 0.5 美元的凭证，再用钱包对它做链下校验
- **THEN** 校验结论为有效，授权增量为 500,000 微美元

#### Scenario: 美元格式错误
- **WHEN** 以 `0.0000001` 作为美元金额签发凭证
- **THEN** 钱包在提交或签名前报错，不产生任何凭证或交易

### Requirement: 工作结算子命令
钱包的 `market` 子命令组 SHALL 增加工作结算命令，用账户的 ML-DSA 密钥签名，并通过节点 RPC 提交或查询：
- 收据：按给定的网关、提供者、模型、token 数、TOPLOC 承诺与时间构造收据，按链上的提供者价格计算费用，以当前账户（提供者或网关）签名并输出收据文件；对已有收据文件追加另一方的签名；按链上公钥与价格校验收据。
- 工作报告：从一组双签收据文件和一组凭证文件构建工作报告（计算 Merkle 根、按提供者与模型汇总），在本地检查汇总与凭证增量一致后提交；显示报告编号与到期纪元。
- 领取：为某账户领取给定纪元的已到期款项。
- 查询：某份报告、某账户的待领取款项与工作量、某纪元的已核验市场工作量。

汇总与凭证增量不一致、收据无效或收据属于其他网关时，钱包 MUST 在提交前报错并指出问题所在的文件。

#### Scenario: 从收据到报告
- **WHEN** 提供者与网关用钱包对两条收据双签，网关用钱包以这两条收据和对应的凭证构建并提交报告
- **THEN** 报告被接受，钱包显示的 Merkle 根与链上报告记录的根相同

#### Scenario: 提交前发现不一致
- **WHEN** 收据的费用合计与凭证的授权增量不一致时构建报告
- **THEN** 钱包报错且不提交交易

#### Scenario: 挑战期后领取
- **WHEN** 报告到期纪元结算后，用钱包为提供者领取该纪元
- **THEN** 提供者余额增加，增加额与查询到的待领取款项一致

### Requirement: 本地推理代理
钱包 SHALL 提供本地推理代理命令：以当前账户为用户，连接一个指定的网关，在本机地址（默认只监听回环地址）提供 OpenAI 兼容接口 `GET /v1/models` 与 `POST /v1/chat/completions`（流式与非流式），使未修改的 OpenAI SDK 只需把 `base_url` 指向代理即可调用。代理 SHALL：
- 启动时校验网关公布的加密公钥属于链上该网关账户，并确认该账户在此网关有透明额度通道，否则拒绝启动；
- 用用户的 ML-DSA 密钥经密封通道转发请求，随附覆盖此前全部已付费请求的累计凭证；
- 收到网关交回的双签收据后，校验签名、创世哈希、网关、模型、token 数与返回的 `usage` 一致，以及费用等于按链上价格计算的值；只有校验通过才签发覆盖该收据的新累计凭证并付给网关；
- 收据校验失败或网关声明的已计费总额与代理自己的记录不符时，停止为该网关付费，拒绝后续请求并报告原因；
- 支持可选的累计花费上限，达到上限后拒绝新请求；
- 把通道的已付总额保存在本地，重启后继续，不重复付费。

用户私钥 MUST NOT 离开本机；代理 MUST NOT 记录 prompt 或输出内容。

#### Scenario: OpenAI SDK 流式调用
- **WHEN** 用官方 OpenAI Python SDK 以代理为 `base_url`、`stream=True` 调用 `chat.completions.create`
- **THEN** SDK 逐块收到生成内容，最后的 `usage` 与网关交回收据中的 token 数相同

#### Scenario: 费用不符时拒绝付费
- **WHEN** 网关交回的收据费用高于按链上价格与 `usage` 计算的金额
- **THEN** 代理不签发凭证，拒绝后续请求并报告费用不符

#### Scenario: 花费上限
- **WHEN** 已付总额达到设定的花费上限后再发请求
- **THEN** 代理拒绝请求且不联系网关

#### Scenario: 重启后不重复付费
- **WHEN** 代理付清若干请求后重启，再发一个请求
- **THEN** 新凭证的累计金额等于重启前已付总额加上新请求的费用

# pallet-audit

推理市场的链上审计（MVP 方案 §5.5；OpenSpec 变更 `m6-audit-chain`；规格 `market/audit`）。审计员在链下用 `ac-auditor` 复核自己发起的推理；本模块决定谁审计谁、记录裁决、处理争议、执行处罚与支付。prompt、回答与证明从不上链（红线 6）：裁决只带证据的承诺，以及（由阈值判定时）几个整数统计量。

## 工作方式

1. **审计员**以美元计的质押登记（按参考汇率向上取整换算）。提供者与网关账户不能登记。质押按固定期限解绑，解绑期内仍可被罚没。
2. **轮次。** 每轮第一个区块记录本轮名单（质押不低于门槛、未在退出中的审计员，按账户排序）与由链上提交-揭示随机数派生的种子。提供者在该轮的审计员为 `ac_primitives::market::audit` 中的 `sample(名单, 种子, 提供者)`，任何人都能复算（`AuditApi::assignment`）。
3. **裁决。** 被分配的审计员每轮对每个提供者提交一次裁决：通过、不通过（原因与证据承诺）或无法判定（原因），附阈值版本与提供者和网关双签的收据。由阈值判定的裁决（通过，或某块超限）还带证据承诺与统计量（`AuditStats`；OpenSpec 变更 `m6-audit-sprt`），其他裁决不带。两个版本都取自收据所载模型的**审计档案**（OpenSpec 变更 `m6-audit-hardening`）：该模型自己的档案（由管理权限在其校准报告入库后设定），或者对于没有自己档案的 BF16 模型，取链的默认档案（正式链没有默认档案）。对未校准模型的裁决被拒绝，`pallet-work` 也不为这类模型计市场工作量（`ModelCalibration`）。链检查收据（本链创世哈希、被审计的提供者、登记的公钥、两个 ML-DSA 签名、按提供者当前价格的费用），并检查其请求 ID 从未被使用过。
4. **争议。** 同一提供者在本轮与上一轮内收到两名不同审计员的“不通过”即开启争议：抽出 `N` 名复核人（排除提出者、提供者与收据的网关），在链下复核证据并投票。一方先达到 `Q` 票即决定结果：
   - **确认**：罚没并销毁提供者的质押，并经 `ProviderPenalty` 将其禁闭（其未结算的工作量由 `pallet-work` 作废）；
   - **驳回**：罚没并销毁每名提出者的质押，并使其退出；
   - 期满后任何人都能把未决的争议关闭，不处罚任何一方。
5. **统计判定。** 每条裁决的统计量为该提供者在该模型上的 CUSUM（`SprtState`，规则见 `ac_primitives::market::audit::stats`；`ModelSprtStates`）加上一个对数似然比。状态达到判定界、统计判定已启用且没有未关闭的争议时，链对状态中的裁决开启**统计争议**（复核人排除这些裁决的审计员、提供者与收据的网关）并把状态归零。复核人由证据重算统计量并重放状态。确认：与上面相同地罚没并禁闭。驳回：不因统计量罚没任何人（统计争议是链的结论，不是某名审计员的指控）。未启用时状态照常计算、可查询，但不开启任何争议。状态或未关闭争议仍引用的裁决超过保留期后移入 `RetainedVerdicts`，不再被引用时删除。
6. **抽查。** 新一轮开始时，链按抽查比例从上一轮由阈值判定的裁决中抽出要复查的裁决：用新一轮的种子与收据请求 ID 抽签（`spot_checked`），每块处理若干个列表；审计员提交时无法预知是否会被抽中。复核人从新一轮名单中抽出（排除该审计员、提供者与网关），只复核结果、不比对统计量（不同硬件上统计量差异过大），投“维持”或“推翻”（`vote_review`）。推翻时该审计员受审计员罚没并退出；抽查从不处罚提供者。
7. **证据可得性。** 复核人在投票时标出没有取得证据的被引用裁决（`vote_dispute` 的位图；`vote_review` 的布尔值）。被 `Q` 张票标出的裁决为“证据不可用”：在任何已决定的争议或抽查中，其审计员只受**轻罚**（活链 1%，不强制退出），而不是完整处罚；在保留期内第 3 次起按完整处罚。
8. **罚没锁与时间窗口。** 当未关闭的争议或抽查引用了某审计员的裁决，或某提供者有未关闭的争议时，它们不能取回解绑中的质押（`Locks`；`pallet-providers` 经 `DisputeLock` 查询）。创世时执行 `check_windows`：两种解绑期与记录保留期都必须覆盖一条裁决可能被引用的 `2R + V` 个区块。
9. **每条裁决至多被裁定一次**（m6-dispute-judged-verdicts，I-030）。不通过争议在开启时裁定它引用的裁决，抽查在开启时裁定它复查的裁决，与结果无关（`Judged`，按轮次与提供者）。不通过争议挑选提出者时跳过已被裁定的裁决，抽查抽签时跳过已被争议引用的裁决，因此审计员不会因同一条裁决受两次处罚。统计争议不裁定任何裁决。裁定记录与其裁决列表一同保留与删除。
9. **支付。** 每条被接受的裁决、每张获胜一方的票，从审计资金池（`PalletId(*b"ac/audit")`）支付固定的美元金额（向下取整）；资金池由国库保底池以“审计”用途注资。资金池不足时跳过支付，从不铸币。

## 参数

| 参数 | 活链草案 | 测试预设 | 护栏 | 修改方式 |
|---|---|---|---|---|
| 轮次长度 | 1,200 个区块（20 分钟） | 20 | > 0 | 创世 |
| 每提供者每轮审计员数 | 2 | 2 | 1–8 | 创世 |
| 复核人数 / 票数门槛 | 5 / 3 | 3 / 2 | 1 ≤ Q ≤ N ≤ 15，2Q > N | 创世 |
| 投票期限 | 600 个区块 | 20 | > 0 | 创世 |
| 提供者 / 审计员罚没比例 | 10% / 10% | 10% / 10% | 1–100% | 创世 |
| 审计员解绑期 | 604,800 个区块 | 60 | ≥ 2R + V | 创世 |
| 轻罚比例 / 升级为完整处罚的次数 | 1% / 3 | 1% / 3 | 不超过审计员罚没比例 / 1–10 | 创世 |
| 审计员质押门槛 | 1,000 美元 | 1,000 美元 | 100–100,000 美元 | 管理权限 |
| 每条裁决或每票的支付 | 0.05 美元 | 0.05 美元 | 0–1 美元 | 管理权限 |
| 抽查比例 | 5% | 50% | 0–50% | 管理权限 |
| 默认审计档案 | 无 | 阈值 `CURRENT_THRESHOLDS_VERSION`、统计 `CURRENT_STATS` | 必须内置，仅 BF16 | 创世 |
| 某模型的审计档案 | 校准报告入库前没有 | — | 必须内置，仅 BF16，只能增大 | 管理权限（`set_audit_profile`） |
| 统计判定是否启用 | 否（待校准覆盖主要 GPU 类别） | 是 | — | 管理权限（`set_stats_enabled`） |

提升某模型的统计判定参数版本会清空该模型的状态：其他版本的状态立即视为空，并在之后的区块中删除，每块两个。

管理权限不能罚没、禁闭、开启或决定任何事情（D6）。

## 调用

`register`、`bond_extra`、`unbond`、`exit`、`withdraw_unbonded`、`submit_verdict`、`vote_dispute`（附没有取得证据的被引用裁决的位图）、`close_dispute`、`set_params`（管理权限）、`set_endpoint`（审计员的证据地址与 X-Wing 公钥，复核人据此取证据；m6-auditor-agent）、`vote_review`、`close_spot_check`、`set_audit_profile` 与 `set_stats_enabled`（管理权限）。调用编号 6（`vote`）与 10（`set_stats_config`）已停用，且不再复用。钱包以 `ac-wallet audit …` 封装这些调用。`AuditApi` 版本 2 增加了证据地址查询与未关闭争议的分页列表；版本 3 返回带统计量的裁决与带种类的争议；版本 4 增加档案、按模型的统计状态、统计判定开关、抽查、罚没锁、抽查计数、证据不可用记录与提供者的所需质押；版本 5 增加某提供者某轮各条裁决的裁定情况（`judged`）。

`vote_dispute` 与 `close_dispute` 先按最坏情形预留权重（对引用 128 条裁决的争议投决定票或关闭），因此任何一笔都放得进区块；执行后按实际工作计费（m6-audit-vote-weights，I-027）：不决定结果的投票只为自己付费（`vote_dispute_open`），决定结果的投票与关闭按争议引用的裁决数计费（`vote_dispute_close(n)`、`close_dispute(n)`）。差额退还手续费并从区块权重中扣回，所以一个区块能容纳多张争议票。

## 存储版本

版本 1（`migrations::v1::MigrateToV1`，由运行时的 `Migrations` 执行）：已存的裁决增加 `stats: None`，争议增加 `kind: Fail`，统计判定以内置的最新版本、关闭状态开始。版本 2（`migrations::v2::MigrateToV2`）：全局的阈值版本与统计参数版本转为默认档案，开关移到 `StatsEnabled`，可调参数加入 5% 的抽查比例，轻罚取活链值，按提供者的统计状态被清空（之后按模型重新累计）。

## 示例

创世参数的护栏：

```rust
use ac_primitives::market::audit::AuditParams;
use pallet_audit::AuditGenesis;

let (fixed, adjustable) = AuditGenesis::LIVE.split();
assert_eq!(fixed, AuditParams::LIVE);
assert!(fixed.check().is_ok());
assert!(adjustable.within_bounds());
let broken = AuditParams { quorum: 2, ..AuditParams::LIVE }; // 5 人中 2 票不是多数
assert!(broken.check().is_err());
```

# pallet-ref-rate

推理市场的 ATC/USD 参考汇率（决策 D23、D29；方案 §5.7）。价格以美元设定，按此汇率以 ATC 结算。

## 单位

- 汇率（`AtcPerUsd`）是每 1 美元对应的 ATC 最小单位数：1 ATC = 10^18 个最小单位，所以“1 ATC = 2 美元”为 `5 × 10^17`。
- 美元金额（`MicroUsd`）是以微美元（10^-6 美元）为单位的整数。
- 换算都注明取整方向：**付款向下取整**（绝不多扣付款方），**门槛向上取整**（最低质押不会因取整被降低）。中间乘积为 256 位，只有结果超过 `u128::MAX` 才失败。

## 交易

| 交易 | 来源 | 作用 |
|---|---|---|
| `set_rate(rate)` | PoA 管理多签 | 设置汇率。汇率必须为正。汇率已设置时，新值必须在旧值的 ±20% 之内（`0.8 × 旧值 ≤ 新值 ≤ 1.2 × 旧值`，含边界），且距上次调整不少于 `min_interval` 个区块。首次设置只要求为正。发出 `RateSet` 事件。 |

汇率未设置时，所有美元换算都会失败，依赖换算的操作（登记提供者或网关、兑付凭证）随之失败。

## 创世

`RefRate.initial`（可选的初始汇率）和 `RefRate.params.minInterval`（活链为 86,400 个区块，即 1 天）。间隔为零或初始汇率为零会使创世失败。`dev` 与 `local` 预设从 1 ATC = 1 美元开始，间隔 10 个区块；活链初始不设置，由管理多签设置。

## 与其他模块的关系

市场模块只经由 `ac_primitives::market::traits::PriceSource` 读取汇率（本模块实现该接口），因此将来可以换成预言机（全量方案 §11），而市场模块的规则不变。M8 会把 `set_rate` 移交给代币治理，并把 ±20% 的约束登记到护栏。

## 功能开关

| 开关 | 默认 | 用途 |
|---|---|---|
| `std` | 是 | 原生构建与测试。WASM runtime 须关闭。 |
| `runtime-benchmarks` | 否 | `set_rate` 的基准测试。 |
| `try-runtime` | 否 | SDK 的 try-runtime 支持。 |

## 示例

英文版 README 中的示例作为 doctest 运行：以 1 ATC = 2 美元换算 100 美元的门槛（50 ATC），1 微美元在每美元 3 个最小单位时付款为 0、门槛为 1，以及 ±20% 的调整边界。

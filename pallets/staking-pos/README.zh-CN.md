# pallet-staking-pos

AgentCoin 的提名式权益证明（方案 §4.3；决策 D19、D24；`m3-pos` 设计 D1–D4）：为 PoA→PoS 切换、验证人选举和罚没提供质押账本。质押、解绑和取回都不铸币也不销毁：质押以 `StakingPos` 锁定原因锁在账户上。

## 角色

一个账户要么是**候选人**，要么是**提名人**，不能同时是两者；更换角色需要账本为空（之前的质押已全部取回）。

- **候选人**注册一个 ML-DSA-65 验证人公钥，并附持有证明：该公钥在上下文 `agentcoin/validator-pop/v1` 下对 SCALE(`"agentcoin/validator-pop-statement"`, 创世哈希, 账户, 公钥) 的签名。这把密钥用于出块、AC-BFT 投票和随机数。公钥永久绑定到一个账户，候选人退出后也不能被他人使用。
- **提名人**锁定一笔金额并提名 1 到 16 个候选人。更换提名对象不需要解绑，从下一次选举起生效。

## 最低额与上限

| | 最低额 | 上限（正式链） |
|---|---|---|
| 候选人自质押 | 总发行量的 0.1% | 500 个候选人 |
| 提名 | 总发行量的 0.001% | 750 个提名人 |

最低额随发行量变化，向上取整。因发行量增长而低于最低额的候选人保留质押，但不算合格（不计入切换条件、不参加选举），直到补足为止。名单已满时，新加入者必须高于名单中最小的一笔；该笔被移出并开始解绑。

## 解绑

申请解绑的质押立即不再计入，但在解锁前仍被锁定：

- 候选人的自质押固定 28 天（2,419,200 个区块）；
- 提名通过全网队列退出，队列能在 28 天内退完全部有效质押：每笔等待 2 到 28 天，同时退出的质押越多等待越长（参照 Polkadot RFC-0097）。

PoA 阶段与 PoS 阶段适用同一规则。候选人用 `retire` 退出；提名人用 `unnominate`（或把质押全部解绑）退出。

## 佣金

5% 到 100%。调高 7 天（604,800 个区块）后生效；调低在下一个验证人纪元生效。生效前可在候选人记录中查到待生效的值。

## 选举

PoS 阶段，每个验证人纪元的最后一个区块为 `K` 个席位运行带平衡的顺序 Phragmén 选举（`sp-npos-elections`），参选者是合格候选人（未暂停参选、自质押达到最低额）和达到最低额的提名人；候选人的自质押算作投给自己的票。结果记录每个当选者的支撑额及其精确构成（验证人本人和各提名人及金额）。切换缓冲期内同一选举以预演方式运行，不改变 PoA 集合。`pallet-validator-set` 以 AC-BFT 权重 `max(1, 支撑额 / 10^12)` 安装当选者。

## 奖励

每次排放结算的安全预算（计划量的 10%，只在 PoS 阶段发放）按工作量而不是按质押分配（决策 D19，规则 R1）：

1. 每个区块为出块人记 1 个工作分。每个纪元边界把刚结束纪元的工作分计入出块人账户——该纪元未揭示随机数的验证人除外，其工作分作废。连续 3 个纪元未揭示则暂停参选。
2. 结算时按工作分在验证人之间拆分预算（向下取整），每份先付该验证人当时生效的佣金，其余按其最近一次选举的支撑构成按比例拆分。取整余数永不铸造。
3. 预算铸入无私钥的奖励池账户（`PalletId(*b"ac/stkrw")`），通过发放队列自动转出，正式链每个区块 256 笔，无需任何领取交易。

## 罚没

每条被记录的双签（`pallet-ac-offences`）只罚验证人本人的自质押，锁定中和解绑中的都算：投票双签 100%，出块双签 10%。同一集合内按最重的一类计算，不累加。罚没的 ATC 经 `Emission` 销毁并计入 `Emission::TotalBurned`；该验证人被暂停参选。提名人永不被罚，掉线不罚本金。

## 固定存储键

由节点的 PoA→PoS 检查读取，永不改名、不改编码：

| 键 | 值 |
|---|---|
| `StakingPos::Ledger`（`Identity` 账户） | `{ active: u128, unlocking: Vec<{ value: u128, unlock_at: u64 }> }` |
| `StakingPos::Candidates`（`Identity` 账户） | `{ key, commission_bps: u32, pending_commission: Option<(u32, u64)>, chilled: bool }` |

## 调用

`register_candidate`、`bond_extra`、`set_validator_key`、`retire`、`nominate`、`set_nominations`、`unnominate`、`unbond`、`withdraw_unbonded`、`set_commission`、`chill`、`validate`。全部权重来自基准测试，每区块钩子（工作分、发放）和选举也一样；注册和提名按扫描满名单的最坏情况收费，未扫描时退还差额。

## 查询

runtime API `StakingApi`：`stake`（账户的有效、解绑中和可取回金额）、`candidate`（候选人记录、当前生效的佣金和收到的提名）、`total_active`、`minimums`、`last_election`（当选者、支撑额及其构成；预演会标明）与 `transition`（阶段、各切换条件及其当前值）。

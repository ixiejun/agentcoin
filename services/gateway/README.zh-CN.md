# ac-gateway

AgentCoin 推理网关（M5，规格 `market/gateway-service`）。用户通过钱包的本地代理（`ac-wallet market serve`）访问它，代理为未修改的 OpenAI SDK 提供本地接口。网关负责：

- 公布由网关账户密钥签名的 X-Wing 公钥（`GET /ac/v1/key`），以及有可服务提供者的模型（`GET /ac/v1/models`）；
- 只经密封通道（`POST /ac/v1/sealed`）接受有额度通道的用户发来的 OpenAI Chat Completions 请求，流式与非流式均可；
- 基于透明额度**后付费**（D54）：请求附带的累计凭证必须**恰好等于**通道的已计费总额，且托管余额必须覆盖已计费但未兑付的总额加上所有在途请求的最大费用。每个请求结束后，用户用一张新总额的凭证付款（单独的 `Pay` 消息）。凭证恰好相等，使每份工作报告的合计都等于兑付增量；
- 路由到价格最低的可服务提供者，同价时选平滑首 token 延迟最低者；首块之前失败会切换到下一个提供者，之后失败则以错误结束且不计费。无法连接的提供者暂停 30 秒，签发无效收据的暂停 1 小时；本阶段不使用 T0/TEE 提供者；
- 校验每条提供者收据（双方、请求、token 数与 `usage` 一致且不超过请求上界、费用等于链上价格）及其 TOPLOC 证明（承诺为全零时不得带证明；否则参数为市场参数、每块输出一份证明、复算承诺等于收据中的承诺，即 `ac_market_proto::toploc::check`），追加签名、计费，连同费用、新总额与证明交给用户，并交还提供者；证明不符的收据按无效收据处理；
- 每 `--report-interval` 个区块提交工作报告，纳入各通道最新凭证覆盖的收据（每份至多 16 张凭证、128 项，超出则拆分）；保留每份报告的收据与证明直到其到期纪元结算，然后领取网关费；
- **从不记录或保存 prompt 与输出**：数据目录只有通道账本、收据与 TOPLOC 证明，日志只含 ID、token 数、费用、延迟与错误码。

## 用法

命令示例见英文版 [README.md](README.md)：用 `ac-gateway keygen` 生成密钥，用钱包登记网关，再运行 `ac-gateway run`。账户必须是链上已登记且活跃的网关。参数：`--report-interval <区块数>`（默认 3,600，不超过一个排放纪元）、`--max-output-tokens`（请求未给出上限时使用，默认 4,096）、`--log-level`。

## 运维

- **TLS**：服务地址公开时，在反向代理处终止 TLS；无论如何请求内容都是端到端密封的。限流也交给反向代理。
- **时钟**：握手有效期为 ±120 秒，请启用 NTP。
- **数据目录**：`channels/`（每个用户一个 JSON 文件：通道号、已计费总额、最新凭证、未报告收据及其 TOPLOC 证明；在确认计费之前写入并落盘）与 `reports/`（已提交报告的收据与证明，保留到到期）。请做好备份：未报告的收据是欠提供者的款项。
